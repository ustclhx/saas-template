## 概要

首个模板版本。覆盖演示站最后一次生产发布 v0.1.3 之后的全部变更，主要包括：

- harden-audit-findings 审查修复：
  - 计费：结账币种锁定；周期变更改为定时生效；月付↔年付在周期末生效。
  - AI：对话免费失败次数与上游超时；媒体取消计费；不确定提交等待回调；存储配额。
  - 认证：防刷与安全响应头。
  - 删号清理：覆盖 AI 内容与增长数据。
  - 发布门禁与迁移安全：squawk、`rollback-safe`、CI 绕过策略。
  - 事件死信队列。
- 模板同步与版本发布：
  - 生成器写入 `.template-base.json`，生成结果确定；
  - `scripts/template-sync.mjs` 同步与基准推断；
  - `template-sync` 技能；
  - 本升级说明体系。
- selfhost：外部 S3 Compose、副本健康预算、部署技能与生成器清单对齐。
- 参考汇率、流式空闲心跳、Node 26 兼容、i18n 修复。

早于本版本生成、没有 `.template-base.json` 的副本，先运行 `template-sync infer-base` 补写基准记录，再同步到 0.2.0。

## 必须执行的动作

1. 部署 jobs 之前，在 Cloudflare 创建事件死信队列 `<项目名>-events-dlq-staging` 与 `<项目名>-events-dlq-production`（`pnpm --dir apps/jobs exec wrangler queues create <队列名>`），名称以 `apps/jobs/wrangler.jsonc` 中的 `dead_letter_queue` 为准。（适用：target=cloudflare）
2. 设置 GitHub 仓库 variable `RELEASE_PHASE`：测试期为 `testing`，上线后为 `live`，未设置时按 `live` 处理。（适用：target=cloudflare）
3. 修改 GitHub `production` environment 的部署分支与 tag 规则，同时允许 `v*` 和 `main`，否则从 main 手动重发、回滚和 hotfix 都会被拦截。（适用：target=cloudflare）
4. 在 `RELEASE_PHASE=live` 阶段，`production` environment 必须配齐 `SENTRY_DSN`、`SENTRY_AUTH_TOKEN`、`SENTRY_ORG`、`SENTRY_PROJECT`，缺任何一个时，生产发布会在构建前失败。（适用：target=cloudflare）
5. 核对 `.github/workflows/deploy-production.yml` 的 `PRODUCTION_URL` 是否为本项目的 HTTPS 地址。旧生成器不会替换这个值，回滚检查会读取它的 `/api/health`。（适用：target=cloudflare）
6. 删除过 job_engine schema（迁移 0013–0015）的项目，二选一：恢复这些表；或同步时用 `--skip-migration 0016_job_engine_app_dead_letter` 跳过授权迁移，并移除或改造 `apps/jobs/src/queues/events-dead-letter.ts` 的死信消费者（它把死信写入 `job_engine` 表，缺表时重试约 100 次后丢弃消息）。
7. 核对副本主机的 `BACKUP_REPLICA_MAX_AGE_SECONDS`：它至少要是 `BACKUP_REPLICA_INTERVAL_SECONDS` 的 3 倍，默认值为 3600，并且要覆盖一次完整同步的耗时。主机上写死的旧值 900 不会被新默认值覆盖，不满足 3 倍时调度器和健康检查都会拒绝。（适用：target=selfhost）
8. 应用文件存储使用外部 S3/R2 时，叠加 `deploy/selfhost/compose.s3.yaml`，在 `.env` 中配置 `S3_ENDPOINT`、`S3_REGION`、`S3_FORCE_PATH_STYLE`，并提供应用专用身份的 `s3_access_key_id`、`s3_secret_access_key` 两个 secret 文件（权限 0600）。（适用：target=selfhost）
9. Stripe 使用受限 key（`rk_`）时，确认它有 Invoices 读取权限。月付↔年付切换入账时会读取发票行。（适用：billing=stripe）

## 配置变更

- `apps/web/wrangler.jsonc` 新增静态资源绑定 `assets.binding: ASSETS`，`run_worker_first` 排除 `/assets/*` 与 `/og/*`。新增其他静态目录时，需要自己补充排除规则。部署时自动生效，不需要创建资源。
- `apps/jobs/wrangler.jsonc` 各环境新增：
  - producer 绑定 `EVENTS_DLQ`；
  - `events` 消费者的 `dead_letter_queue`；
  - DLQ 消费者（`max_retries: 100`）。

  需要的队列见上文动作 1。
- 两个 Worker 的 production 环境开启 `observability` 日志（`head_sampling_rate: 1`），日志量和费用会增加。
- 新增运行时设置：
  - `ai.freeFailures`：默认每个工作区每 3600 秒 3 次，可在后台修改；
  - `ai.mediaUncertainWaitSeconds`：默认 3600，没有后台入口。

  两项都有默认值，不需要手动设置。
- 发布工具：
  - 新增 `RELEASE_PHASE` 与 CI 绕过策略；
  - 门禁脚本取自 main；
  - CI 新增 squawk 迁移检查（根 devDependency `squawk-cli`）；
  - 新迁移需带 `-- rollback-safe:` 注释，才允许回滚到旧版本。
- 生成器新增 `.template-base.json`，需提交到项目仓库。
- `packages/config` 的环境校验、`.dev.vars.example` 的键、Worker secrets 都没有变化，也没有新增需要订阅的支付 webhook 事件。

## 数据库变更

### 0016_job_engine_app_dead_letter

- 类别：扩展
- 兼容上一版本代码：是
- 锁表与耗时：只修改授权元数据，可以忽略
- 回滚：只回退代码，保留授权

`app` 角色获得 `job_engine` schema 的 USAGE，以及 `queue`、`message`、`dead_letter` 三张表的 SELECT/INSERT 权限，供 Cloudflare 事件死信消费者写入。依赖 0013–0015 建立的 `job_engine` schema 与 `app` 角色。

### 0017_audit_meta_remove_personal_data

- 类别：数据迁移
- 兼容上一版本代码：是
- 锁表与耗时：对 `audit_log` 执行两条全表 UPDATE（没有 `action` 索引，耗时随行数增长），只锁定命中的行，不阻塞追加写入；迁移设置了 `lock_timeout=5s`、`statement_timeout=15min`。selfhost 的 migrate 容器有 300 秒上限，审计表很大时要预估耗时
- 回滚：不可逆，旧格式中的个人信息已被删除。代码可以回退，数据只能从备份恢复

改写历史审计元数据：`workspace.member_invited` 删除被邀请人邮箱；代登录修改资料改为只记录字段名。

### 0018_ai_task_cancel_billing

- 类别：扩展
- 兼容上一版本代码：是
- 锁表与耗时：`ai_task` 新增可空列、部分唯一索引和 CHECK 约束，需要 ACCESS EXCLUSIVE 锁并全表扫描，持有锁直到迁移事务结束，会阻塞 `ai_task` 的读写。拿不到锁时 5 秒超时，迁移失败，可以重试
- 回滚：只回退代码，保留新列、索引和约束

记录媒体任务的取消计费方式，并用部分唯一索引保证每个工作区终身只有一次「已开始免费取消」。
