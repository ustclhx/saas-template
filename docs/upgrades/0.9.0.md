## 概要

本版本包含三个已合并的 OpenSpec change、一项媒体修复和一项 Node 构建修复：构建期插件机制（add-plugin-system）、Agent 对话（add-ai-agents）、管理员 MCP 与功能模型沿用（add-admin-mcp）。

不兼容点：
- `template.config.ts` 的 `ai.mediaProviders` 已删除，改为 `plugins.media.providers`；
- 图片 / 视频任务的源码从 `apps/web`、`apps/jobs` 移到 `plugins/media`；
- Cloudflare web 需要新的限流绑定 `RL_ADMIN_MCP`；
- 已有 Cloudflare 衍生项目（启用计费和积分）同步后会**默认启用 `agents`**，带来 `AGENT_CONVERSATION` Durable Object 及其迁移 `agents-v1`。不需要 Agent 的项目必须在**首次部署前**删除，见「必须执行的动作」2、5；
- `packages/db/src/settings.ts` 改为定义表，项目自加的设置键要移到项目自有文件。

- **构建期插件**（#449、#451、#453–#455、#459）：
  - 插件是 `plugins/<id>` 下的 workspace 包（`@saas/plugin-<id>`），源码随项目保留。构建按 `template.config.ts` 的 `plugins` 选择要挂载的路由、入口、文案和 Tailwind 扫描目录。注册文件 `apps/web/src/plugins*.gen.ts`、`apps/jobs/src/plugins*.gen.ts` 与 `apps/web/src/styles/plugins*.gen.css` 由 `scripts/plugins/generate.mjs` 生成，已加入 gitignore。
  - 扩展点：`appNav`、`adminNav`、`toolRenderers`、Worker `fetch`、jobs 的 `queues` / `crons` / `holdSweepers`、Node 入口，以及插件可贡献的 `agentTools`。
  - 媒体任务迁入 `plugins/media`，支持 Cloudflare 和 Node，要求启用 `billing` 和 `credits`。
  - 生成器新增 `--plugins`；省略时按部署目标和功能开关筛选模板默认插件，`--ai` 含 `image` 或 `video` 时自动加入 `media`。template-sync 按 `params.plugins` 重建副本；记录里没有这个键时使用目标版本的默认插件。
  - `pnpm check` 新增 `scripts/check-plugins.mjs`，检查清单路径、各环境是否有插件所需的绑定，以及是否还留着已停用插件的类绑定。
  - 说明见 [插件开发与部署](../plugins.md)。
- **Agent 对话**（#450、#452、#456–#458、#460–#465，`agents` 插件，仅 Cloudflare）：
  - 持久对话、多步工具、人工确认和按轮次计费，页面位于 `/app/$slug/agents`。
  - 实现细节：对话实例是 web Worker 导出的 `AgentConversation` SQLite Durable Object；每轮在 PG 写入 `ai_agent_turn` 并预扣积分。
  - 支持删除对话和删号清理、可选保留期，以及媒体异步工具 `generate_image` / `generate_video`（启用 media 时可用，调用前需要确认）。
  - 文本模型新增「支持工具调用」开关（`supports_tools`），默认关闭；Agent 只能选择开了这个开关的模型。
  - 说明见 [Agent 对话](../06-ai.md#8-agent-对话pluginsagents)。
- **管理员 MCP**（#467–#475，`admin-mcp` 插件，Cloudflare 与 Node，模板默认启用）：
  - 平台管理员在后台「API 令牌」页（`/admin/api-tokens`）创建个人令牌，连接远程 MCP 端点 `/api/admin/mcp`。
  - 提供 14 个工具：12 个只读，`settings.set` 与 `models.update` 两个写工具。写工具支持 `dryRun` 预览。
  - 调用记入审计（`via: "mcp"`），默认每个令牌每分钟 120 次。
  - 说明见 [管理员 MCP](../admin-mcp.md)。
- **运行时设置定义表**（#469）：
  - 模板设置由 `templateSettings` 用 `defineSetting` 定义（schema、默认值、说明，需要脱敏的项标 `secret`）。
  - 项目自己的设置在项目自有文件 `packages/db/src/settings.project.ts` 中登记，`getSettingValue` 按字符串键读取。
  - 后台和 MCP 保存时都用同一份定义校验。见 [运行时设置定义](../02-project-structure.md#运行时设置定义)。
- **功能模型沿用**（#469）：
  - 在项目自有文件 `packages/ai/src/feature-models.project.ts` 中用 `defineFeatureModels` 登记功能、模型种类和沿用顺序，每个功能会自动得到运行时设置 `ai.model.<feature>`。
  - 服务端用 `@saas/ai` 的 `resolveFeatureModel(db, settingsCtx, feature)` 解析，返回实际使用的模型和来源（显式选择、沿用、未设置）。
  - 后台设置页新增「功能模型」分组。见 [功能模型](../06-ai.md#功能模型)。
  - **可选**：项目里已有自己维护的「按功能选模型、兄弟功能回退」代码（例如某衍生项目的 `apps/web/src/features/readings/config.ts`）的，可以改为在 `feature-models.project.ts` 登记并调用 `resolveFeatureModel`，换来后台 / MCP 可调和来源可查。不改也能继续工作。
- **媒体修复**（#466）：服务商明确拒绝的提交（4xx，429 除外）不再重试，并保留原错误码，例如密钥失效的 401 不再被记成泛化的 `MEDIA_GENERATION_FAILED`。
- **Node 构建预渲染修复**（#478）：`pnpm build:node` 预渲染 `/`、`/zh` 时，lucide 图标组件报 `useContext` 为 null，页面只渲染出空壳。原因是产物里同时存在两份 React。
  - `apps/web/vite.node.config.ts` 的 SSR 输出关闭 `polyfillRequire`，`require` 统一交给 Nitro 解析，所有引用用同一份 React。
  - `build:node` 新增 `scripts/check-node-requires.mjs` 检查：产物中的 `__require` 只允许指向 Node 内置模块。
  - Cloudflare 构建不受影响。
- 模板仓库自身的维护脚本（#476，`scripts/orca/prune-dbs.sh` 等）不影响衍生项目。

## 必须执行的动作

1. 迁移媒体服务商配置：从 `template.config.ts` 删除 `ai.mediaProviders`；启用 media 的项目改为在 `plugins: { media: { providers: [...] } }` 中保留原来的服务商列表。不启用 media 的项目不写 `media` 键，并把 `ai.image`、`ai.video` 都设为 `false`（否则插件校验报错）。template-sync 生成的同步参照会自动带上这段改动；项目改过这几行而产生冲突时，按上述规则手动合并。项目代码中读取 `templateConfig.ai.mediaProviders` 的地方改用 `@saas/config` 的 `getMediaProviders(templateConfig)`。
2. 核对插件选择：同步后 `template.config.ts` 会出现 `plugins` 段，内容是目标版本按 `.template-base.json` params 选出的默认插件。`admin-mcp` 总是启用；params 的 `ai` 含 `image` 或 `video` 时启用 `media`；部署目标是 Cloudflare 且启用了计费和积分时启用 `agents`。**也就是说，已有 Cloudflare 衍生项目同步后会默认启用 agents；不需要时，必须在首次部署前删掉 `plugins.agents`、`AGENT_CONVERSATION` 绑定和 `agents-v1` 迁移项（见动作 5），否则以后移除会清空全部对话。**不需要某个插件时，删掉它的键和专属绑定（见动作 4、5），`pnpm check` 会列出需要删除的绑定。同步到 0.9.0 之前，不要手动在 `.template-base.json` 里加 `params.plugins`：0.8.x 的生成器不认识这个参数，基准副本会生成失败。
3. 迁移被移动的媒体源码：`apps/web/src/features/ai-media/*` 移到 `plugins/media/src/web/ai-media/*`。其余移动：`features/ai/media-tasks.ts` → `plugins/media/src/web/media-tasks.ts`，`features/api-keys/tasks.ts` → `plugins/media/src/web/public-tasks.ts`，`routes/api/ai/tasks*`、`routes/api/v1/tasks*`、`routes/api/webhooks/media/$provider.ts`、`routes/api/dev/workflow.ts`、`routes/app/$slug/media/new.tsx`、`routes/app/$slug/tasks/*` → `plugins/media/routes/` 下的同名路径（URL 不变），`apps/jobs/src/workflows/media-runner.ts` → `plugins/media/src/jobs/media-runner.ts`，媒体文案 `apps/web/messages/<locale>/ai-media*.json` → `plugins/media/messages/<locale>/`。template-sync 按重命名三方合并：项目没改过的文件直接移动，改过的会合并项目修改，冲突处保留标记。若项目在旧路径上新增了自己的文件或引用，移到插件目录，或通过插件的 web 入口扩展点（`appNav`、`adminNav`、`toolRenderers`）接入。旧路径上留下的路由文件可能和插件路由注册同一个 URL。`apps/jobs/src/observer.ts` 已删除，`JobObserver` 改为从 `@saas/shared/log` 导入。
4. 为 Cloudflare web 新增限流绑定 `RL_ADMIN_MCP`：在 `apps/web/wrangler.jsonc` 的顶层、`env.staging`、`env.production` 的 `ratelimits` 中各声明一次（`simple: { limit: 120, period: 60 }`）。模板占位值依次为 1013、1014、1015，项目按账号内未被占用的值分配，三处互不相同，也不与其他限流绑定重复（`pnpm check` 中的 `check-wrangler-envs` 会检查）。停用 `admin-mcp` 的项目不需要这个绑定。（适用：target=cloudflare）
5. 决定是否启用 Agent：保留 `agents` 时，确认 `apps/web/wrangler.jsonc` 的顶层、`env.staging`、`env.production` 都有 `durable_objects.bindings` 中的 `AGENT_CONVERSATION`（`class_name: "AgentConversation"`；`durable_objects` 不继承，各环境分别写），并且顶层 `migrations` 有 `{ "tag": "agents-v1", "new_sqlite_classes": ["AgentConversation"] }`。项目已有自己的 Durable Object 迁移时，`agents-v1` 追加在末尾，tag 不能和已发布的重名。在后台为要用于 Agent 的文本模型打开「支持工具调用」。不打算使用 Agent 的项目，在**首次部署前**删掉 `plugins.agents`、三处 `AGENT_CONVERSATION` 绑定和 `agents-v1` 迁移项：部署过一次之后，要移除这个类就得追加 `deleted_classes` 迁移，这会清空全部对话。（适用：target=cloudflare; billing-enabled=true）
6. 处理新增的项目自有文件：`packages/db/src/settings.project.ts`、`packages/ai/src/feature-models.project.ts`、`plugins/agents/src/agents.project.ts`、`plugins/agents/src/tools.project.ts` 由本版本首次交付。template-sync 把它们当作新增文件写入项目，以后不再覆盖。项目在 `packages/db/src/settings.ts` 的 `SettingValues` / `settingDefaults` 里自己加过的键会与新的定义表冲突：解决冲突时保留模板版本，把这些键用 `defineSetting` 移到 `settings.project.ts`，原有的 `getSetting(ctx, key)` 调用不用改。
7. 自定义了部署工作流的项目：在 Cloudflare 的 jobs / web 构建步骤之前执行 `node scripts/plugins/generate.mjs`，参照模板的 `.github/workflows/deploy-staging.yml`、`deploy-production.yml`。selfhost 镜像上下文要包含 `plugins/` 和 `scripts/plugins/`，参照 `deploy/selfhost/app.Dockerfile.dockerignore`。没有自定义的项目由三方合并自动完成。
8. 同步后运行 `pnpm install`（新增了 `plugins/*` workspace），再运行 `pnpm check`、`pnpm typecheck`、`pnpm build`；selfhost 项目另外运行 `pnpm build:node`。按 `check-plugins` 的提示补齐或删除绑定，例如未启用 media 的项目要删掉 `AI_MEDIA_WORKFLOW`。

## 配置变更

- 删除 `ai.mediaProviders`。
- 新增 `plugins: Record<插件 id, 配置段>`，默认 `{}`。未出现的插件不进入路由树与入口。
  - `plugins.media.providers?: ('fal' | 'workers-ai')[]`：省略时为 `['fal', 'workers-ai']`。
  - `plugins.agents`：`maxSteps`（默认 8，范围 1–50）、`maxTurnCredits?`、`maxPersistedMessages`（默认 200）、`retentionDays?`（不设置即关闭）、`defaultAgent`（默认 `'assistant'`）。
  - `plugins['admin-mcp']`：`rateLimitPerMinute`（默认 120，只用于 Node；Cloudflare 的额度由 `RL_ADMIN_MCP` 绑定决定）、`maxTokenDays`（默认 365，上限 365）。
- 新增运行时设置 `ai.model.<feature>`：每个登记的功能一个，空字符串表示沿用或未设置。
- Cloudflare web 新增绑定：`RL_ADMIN_MCP`（rate_limit）；启用 agents 时还有 `AGENT_CONVERSATION`（durable_object）与迁移 tag `agents-v1`。没有新增密钥。media 仍使用原来的 `FAL_KEY`、`MEDIA_WEBHOOK_SECRET`、`AI_MEDIA_WORKFLOW` 与可选的 `AI` 绑定。
- 生成器新增 `--plugins`；`.template-base.json` 只在实际选择与默认值不同时记录 `params.plugins`。
- `pnpm-workspace.yaml` 新增 `plugins/*`，`turbo.json` 的构建输入新增 `plugins/**` 与 `scripts/plugins/**`。

## 数据库变更

### 0025_ai_agent_turn

- 类别：扩展
- 兼容上一版本代码：是
- 锁表与耗时：新建表 `ai_agent_turn` 和它的外键、索引不影响已有数据。`ai_conversation` 新增 `kind`（常量默认值 `'chat'`）、`agent_id`（可空），`ai_model` 新增 `supports_tools`（常量默认值 `false`），PG 11 起这些都只改元数据。`ai_conversation` 的两个 CHECK 约束在同一条 `ALTER TABLE` 中添加，需要持有 ACCESS EXCLUSIVE 锁扫描一遍全表；对话表在百万行以内时预计秒级。迁移设置了 `lock_timeout = 5s`、`statement_timeout = 30s`，超时会失败而不会长时间阻塞。
- 回滚：只回退代码。旧代码不读取新表和新列；`kind` 有默认值，旧代码写入的对话仍满足约束。不自动删除表或列。

新增 Agent 轮次表（定价快照、预扣、用量检查点、步数、工具调用状态），并给对话加上类型和 agent 标识，给模型加上工具调用能力标记。

### 0026_admin_api_token

- 类别：扩展
- 兼容上一版本代码：是
- 锁表与耗时：只新建 `admin_api_token` 表、唯一索引 `token_hash` 与 `user_id` 索引，以及到 `user` 的外键（`ON DELETE CASCADE`）。添加外键时会短暂锁住 `user` 表，预计毫秒级；迁移设置了 `lock_timeout = 5s`、`statement_timeout = 30s`。
- 回滚：只回退代码。旧代码不访问这张表，不自动删除。

存放管理员 API 令牌：只存 SHA-256 摘要和前缀，另有 scope、有效期、最近使用时间和吊销时间。停用 `admin-mcp` 的项目也会应用这个迁移（迁移统一由 `packages/db` 管理）。

## 部署顺序

1. 完成「必须执行的动作」4、5：在各环境声明 `RL_ADMIN_MCP`；决定是否保留 agents 并相应处理绑定和迁移项。`pnpm check` 通过后再继续。
2. 应用数据库迁移 `0025_ai_agent_turn`、`0026_admin_api_token`。两个都是扩展迁移，可以在旧代码运行时先执行。
3. 按原有顺序先部署 jobs，再部署 web；模板 CI 的顺序是迁移 → jobs → web。启用 agents 时，web 首次部署会执行 Durable Object 迁移 `agents-v1`。
4. selfhost：用包含本版本代码的同一 SHA 镜像发布，`deploy.sh` 先迁移再切换服务；agents 不参与 Node 构建。

不需要 `requiresDeployed`。

## 回滚

- 回退本版本代码并重新部署即可，数据库迁移都是扩展迁移，旧代码可以继续运行，不回退结构。
- 回滚前把 `template.config.ts` 的 `plugins` 改回 `ai.mediaProviders`，否则 0.8.1 的类型检查不通过。同时删除 `RL_ADMIN_MCP` 绑定，或保留它（旧代码不使用这个绑定）。
- **Agent 例外**：web 一旦带着 `agents-v1` 部署，Cloudflare 就不允许把它回滚到 Durable Object 迁移之前的版本。删除 `AgentConversation` 类需要追加 `deleted_classes` 迁移，会清空全部对话消息，要先确认。已部署 agents 的项目建议向前修复：保留 agents 插件，只回退其他改动；或者把要回滚的代码与 `AgentConversation` 导出一起保留。
- 回滚后，已创建的管理员 API 令牌和 Agent 轮次数据保留在数据库中，重新升级后继续可用。

## 已知问题

- add-plugin-system 任务 7.1 **未验收**：迁入 `plugins/media` 后，staging 的图片和视频回归尚未完成，原因是 staging 的 `FAL_KEY` 无效，要等使用者更换。本地测试和四种生成副本已通过；启用 media 的项目升级后请按「验证」先在 staging 各跑一条图片和视频任务，再上生产。
- Agent 对话的消息只存在 Durable Object 实例的 SQLite 中，不在 PG 备份恢复范围内；单个实例只能用 Cloudflare 30 天内的时间点恢复。
- Cloudflare 原生限流绑定目前在线上不生效（与 `RL_AUTH` 等相同），`RL_ADMIN_MCP` 也是这样；在此之前由令牌校验和管理员角色检查兜底。
