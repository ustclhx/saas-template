## 概要

- **提示词版本与评测（add-prompt-evals）**：`@saas/ai` 新增提示词定义工具，新增只供命令行使用的评测包 `packages/evals` 与根脚本
  `pnpm eval:prompts --suite <name>`：固定样本、多个提示词版本、默认离线回放、可选真实模型（必须给美元预算上限）、确定性检查、
  LLM 评委、报告与基线对比。完整说明见 [AI §3「提示词版本与评测」](../06-ai.md#提示词版本与评测add-prompt-evals)。
- 提示词评测部分同步后没有运行时行为变化：没有迁移、没有部署变化，`packages/evals` 不进入任何 Worker 或自托管产物。
- **对话组件（add-ai-chat-components）**：对话页与嵌入式 SubjectChat 改用 `@<scope>/ui/chat` 组件（Markdown 回复、推理折叠、工具卡片、
  停止 / 失败 / 未完成状态、状态播报），SubjectChat 改为 `EmbeddedChat` 外壳；**不兼容**：删除 `ChatPage` 的 `variant="embedded"`，
  新增项目自有文件 `message-parts.project.tsx`。详见下方小节。

- **分享卡片韩文与运行时语言（add-share-card-project-overrides 跟进）**：底部副标题不再被裁掉半个字；韩文标题与摘要按词换行；
  多语言多站点项目的运行时卡片按分享页语言显示品牌。没有站点覆盖的项目卡片地址不变，渲染结果只在原先会被裁切的副标题上变化。
- **Stripe 门户周期末取消（缺陷修复）**：Customer Portal 的周期末取消（只设置 `cancel_at`）现在映射为周期末取消，账单页不再显示续费中；
  恢复与换套餐同样识别该形态。账单页「当前套餐」显示套餐名而不是权益 key。没有迁移。详见下方小节。
- **文本模型显式 `thinking=false` 下发关闭（缺陷修复，xuanxue 反馈）**：模型 `x-text.thinking=false` 时，可控 Provider（DeepSeek）的请求现在带
  `thinking.type=disabled`，不再省略；推荐问题对可控 Provider 总是显式关闭思考。提示词评测评委输出上限可配置（缺省 4096）并缺省关闭思考，
  生成与评委改用 `instructions` 传 system。详见下方小节。

### 文本 thinking 显式关闭与评测真实模式

- **现象**（xuanxue 以 DeepSeek V4 flash 实测）：模型行配置 `x-text.thinking=false` 时，`chat.ts` 经 `supportsTextThinking` 得到 false，
  向 `createChatStream` 传 `thinking: undefined`，请求不带任何思考设置；DeepSeek V4 默认推理，reasoning token 计入 `maxOutputTokens`，长回复被截断。
- **修复**：`@<scope>/ai` 新增导出 `resolveTextThinking(provider, override, requested)`（Provider 不可控 → `undefined`；`override === false` → `false`；
  否则 `requested`）。站内对话与 `/v1/chat/completions` 用它计算 thinking，`x-text.thinking=false` 的 DeepSeek 模型下发 `reasoning: 'none'` 与
  `providerOptions.deepseek.thinking.type='disabled'`。用户开关仍不开放（`supportsTextThinking` 语义不变，只用于是否显示开关）。
  推荐问题（`follow-ups.server.ts`，上限 256 token）对可控 Provider 总是显式关闭思考。其他 Provider 没有 adapter，请求不变（逐 Provider 说明见
  [AI · thinking](../06-ai.md#thinkingreasoning-与自动恢复)）。
- **行为变化**：显式 `thinking=false` 的 DeepSeek 模型请求多出关闭参数；依赖“不下发”的项目测试（如断言 `providerOptions.deepseek` 为 undefined）需改为断言关闭形式。
- **评测（`packages/evals`，真实 / 录制模式此前未对真实 Provider 运行过）**：
  - 生成与评委的 `generateText` 改用 `instructions` 传 system（AI SDK 7 中 `system` 已弃用；system 放进 `messages` 需要 `allowSystemInMessages`），请求形状对所有 Provider 一致；回放不受影响。
  - 套件 `judge` 新增可选 `maxOutputTokens`（正整数，缺省由 1024 提到 4096）与 `thinking`（缺省 `false`：评委模型 Provider 可控时显式关闭思考）。
    预算估算按该上限计算（reasoning token 含在上限内），因此**真实 / 录制模式下每次评委调用的预留额约为原来的 4 倍**；预算紧的项目可在套件中调低 `judge.maxOutputTokens`。
  - 套件模型声明新增可选 `thinking?: boolean`，与线上模型行 `x-text.thinking` 同一语义：缺省不改请求；声明后生成调用经
    `resolveTextThinking` + `applyThinking` 下发开 / 关（Provider 可控时）。按线上模型行声明，评测即与线上一致。该字段不进渲染摘要、版本锁与录制，
    改动后不会被判为过期，需自行重新录制。
  - `JUDGE_MAX_OUTPUT_TOKENS` 现为 4096，`runJudge` 新增第四个参数 `settings`（`judgeSettings(provider, judge)` 生成）。录制文件格式与渲染摘要不变，现有录制继续有效。

### 对话组件（add-ai-chat-components）

  标题行（「全部对话」返回、标题、对话操作菜单：新对话 / 归档）留在对话区头部、不进顶部条；输入区吸附在视口底部（短对话与空态也贴底，

  回复结束（完成、停止、出错、断开）后 `ChatSession` 经新 Server Function `getChatMessage` 读取已保存的消息，把正文、状态、积分与模型
  换成保存（并计费）的版本，不刷新即显示消耗；停止后服务端多生成的那段正文也会出现，与刷新后一致（消息仍为 streaming 时按退避重读，

  生成中上翻时出现「回到最新」；错误与余额不足提示移到输入框上方，被拒的消息放回草稿。路由新增加载骨架（`ChatPageSkeleton`）。

### 分享卡片韩文与运行时语言

- **副标题裁切**（xuanxue 反馈：「간지데이 · 무료 만세력·사주·타로」只显示半个「로」）：不是截断造成的。satori 测量时 `·`、空格用 Inter，
  绘制时同一词段用段首字符的字体（谚文段用项目字体、汉字段用 Noto Sans SC，`·` 更宽），副标题盒宽等于测量宽度，`overflow: hidden`
  把多出的部分裁掉。中文副标题里不带空格的 `·`（如「免费万年历·八字·塔罗」）同样受影响。现在副标题盒子占满域名左侧的剩余宽度，
  上限随域名宽度收紧（`metaLimit`），仍超出时 satori 在字素边界加省略号。纯拉丁与没有该差异的卡片像素不变（已用模板字体比对 PNG 字节）。
- **韩文换行**：标题与摘要含谚文且不含汉字、假名时设置 `wordBreak: 'keep-all'`，在空格处换行（不再出现「개 / 인정보」）；
  `countLines` 新增第三个参数 `keepAll`（默认按新导出的 `keepsWords(text)` 判断），截断仍保证两行内。中日文与拉丁标题的版式不变。
  项目自建版式显示韩文段落时同样设置 `keep-all`。
- **运行时语言**：通用分享页与 `shareCardMeta` 把页面语言作为 `context.locale` 传给 `resolveProjectShareCardSite`；
  站点覆盖生效且语言不是默认语言时，卡片地址追加 `&l=<locale>` 并计入 `v`。卡片路由与 `/dev/ui` 预览只接受 `template.config.ts`
  启用的语言，缺省或未知值按默认语言。默认语言、以及没有站点覆盖的项目地址不变（已发出的卡片地址继续有效）。
  `resolveRequestShareCardSite` 新增可选的第四个参数 `locale`。
- 运行时 `context.locale` 现在总有值（缺省为默认语言），此前卡片路由传入 `undefined`。解析函数若以 `locale === undefined` 判断默认语言，
  改为与默认语言比较。

### Stripe 门户周期末取消与当前套餐名称

- **现象**（xuanxue staging 验收在 Stripe 测试模式、API `2026-09-30.endive` 实测）：在 Customer Portal 选择「周期末取消」后，
  Stripe 设置 `cancel_at`=当前周期末、`canceled_at` 有值，但 `cancel_at_period_end` 仍为 false。模板只映射 `cancel_at_period_end`，
  本地订阅仍按「会续费」处理：账单页显示续费中、`current()` 与「会续费订阅」部分唯一索引把它算作续费订阅（阻止换平台重叠），
  应用内「恢复续费」只发 `cancel_at_period_end: false`、清不掉 `cancel_at`，换套餐也不会要求先恢复。
- **修复**（`packages/billing/src/stripe/snapshots.ts`、`operations.ts`）：新增导出 `stripeCancelsAtPeriodEnd(subscription, currentPeriodEnd)`
  = `cancel_at_period_end || (cancel_at != null && cancel_at <= 订阅项 current_period_end)`，快照映射与换套餐检查共用；
  `resumeStripeSubscription` 先读取订阅，Portal 形态发 `cancel_at: ''` 清除，其余仍发 `cancel_at_period_end: false`（因此恢复多一次 GET）。
  `cancel_at` 晚于当前周期末的远期定时取消不算周期末取消（下一周期仍续费）；项目若自行设置这种取消，需要自己处理展示。
- **当前套餐名称**：`getEntitlements` 的结果新增可选 `name`（套餐显示名，内置免费兜底没有）；账单页「当前套餐」改用
  `entitlementPlanName`（`features/billing/billing-sections.tsx`）：先取权益自带名称（已下架、不在目录中的套餐也能显示），
  再按目录匹配，未落库的免费档显示「免费套餐」文案，不再显示 `plus`、`free` 之类的 key。项目对 `Entitlements` 做整体相等断言的测试需加上 `name`。
- **存量数据**：不需要迁移。已被门户取消、本地仍显示续费的订阅，会在部署后下一次每日订阅对账时改正：jobs 的 `BILLING_DAILY_CRON`
  （`0 4 * * *`，`apps/jobs/src/billing.ts`）调用 `runSubscriptionReconciliation`（`packages/billing/src/cron.ts`），对状态为
  active / trialing / past_due / paused 的订阅逐个 `provider.getSubscription` → `stripe.subscriptions.retrieve` 并按新映射写回。
  jobs 未部署或该 Cron 未启用时，要等该订阅的下一条 Stripe 事件，最晚为周期末的 `customer.subscription.deleted`。需要立即改正时，
  在 Stripe Dashboard（Workbench → Events）或 CLI（`stripe events resend <evt_id>`）重发受影响订阅最近的 `customer.subscription.updated`。
- 改过 `packages/billing/src/stripe/*` 或账单页的项目按冲突逐处合并。

### 提示词版本与评测（add-prompt-evals）

- **`@<scope>/ai` 新导出**（`text/prompt.ts`，业务无关、无新依赖）：`definePrompt`、`renderPrompt`、`promptCanonicalJson`、`promptSha256`、
  `renderedPromptDigest` 与类型 `PromptDefinition`、`DefinedPrompt`、`PromptSection`、`PromptParams`、`RenderedPrompt`、`RenderedSection`。
  `definePrompt` 返回带 `promptVersion`（`<id>@<version>`）的冻结定义。
- **新包 `@<scope>/evals`**（私有，依赖 `@<scope>/ai`、`ai`、`zod`）：套件与版本锁、内置检查（章节、长度、禁用词与正则、文字占比、简繁误用）、
  美元预算账本、LLM 评委、回放 / 真实 / 录制三种模式、报告与基线、命令行入口；自带示例套件 `packages/evals/example/`。
  包单测（示例套件离线回放）随 `pnpm test` 运行，不发出真实调用。
- **根 `package.json`**：新增脚本 `eval:prompts`（`node --experimental-strip-types packages/evals/src/cli.ts`，存在时由入口加载根目录 `.env.local`）
  与开发依赖 `@<scope>/evals: workspace:*`。该脚本不在 turbo 任何任务中；`CI` 为真时拒绝 `--live` / `--record`，且版本锁冻结（缺条目即配置错误）。
- **依赖检查**：`pnpm check:deps` 新增规则——除根 `package.json` 外，任何 app 或 package 的 manifest 与源码（含测试）都不得依赖或引用 `@<scope>/evals`。
- **项目自有目录 `evals/`**：项目套件放在根目录 `evals/<suite>/`。模板永远不在该目录交付文件（模板侧 `template-release check` 会拒绝），
  `template-sync` 因此不会新增、覆盖或删除其中的文件。
- **报告位置**：`$EVIDENCE_DIR/prompt-evals/<suite>/…`，未设置时为已被 `.gitignore` 忽略的 `test-results/evidence/`，不进仓库。

- 新增目录 `packages/evals/`（模板拥有，同步时正常更新）。项目自己的套件不要放进该目录，放在根目录 `evals/<suite>/`。
- 真实或录制模式使用与线上相同的文本模型出口变量（`AI_TEXT_EGRESS`、`OPENAI_BASE_URL`、`AI_GATEWAY_ACCOUNT_ID`、`AI_GATEWAY_ID`、
  `AI_GATEWAY_TOKEN` 与各服务商 API key 的名称），从本地 `.env.local` 读取；没有新增必填变量或密钥。
- **衍生项目接入（可选）**：
  1. 用 `definePrompt` 在功能目录定义提示词（模块保持纯函数、只用可类型剥离的 TS 语法），生成时用 `renderPrompt`；
  2. 在项目自有的生成表加列 `prompt_version text not null`，写入 `promptVersion`，结构化日志同时记录该字段（模板的 `ai_message` 不加此列）；
  3. 建 `evals/<suite>/suite.ts`、`samples.json`（只放合成或脱敏数据），模型声明美元单价；
  4. 先 `pnpm eval:prompts --suite <suite> --record --budget-usd <美元>` 录制一次并提交录制与 `prompts.lock.json`，
     之后改提示词时新建版本，用 `--baseline <旧版本>` 离线回放对比。

## 回滚

回退代码即可：删除 `packages/evals`、根 `package.json` 的 `eval:prompts` 脚本与 `@<scope>/evals` 开发依赖，以及 `packages/ai/src/text/prompt.ts` 的导出。
项目已在自有生成表加的 `prompt_version` 列与 `evals/` 套件由项目自行保留或删除。
分享卡片的修复回退代码即可；非默认语言的卡片地址回到不带 `l` 的地址，旧地址按 `v` 不符 302 到当前地址。

## 已知问题

- 示例套件的回放录制目前是按格式手写的（`source: "constructed"`），用于离线验证工具本身，不代表真实模型的输出质量；真实录制待补。
- 简繁检查只覆盖约 500 个常用「仅繁体」字及对应简体字，罕见字可能漏检；需要更严格的判定时用自定义检查替换。
- 分享卡片：satori 用段首字体绘制整段的差异同样存在于标题与摘要（satori 按测量宽度换行），某行恰好排满且含多个 `·` 等标点时，行尾可能比内容区右缘多出几像素而被标题盒裁掉；验收样例中未出现。根治需要 satori 按绘制字体测量，待上游。
