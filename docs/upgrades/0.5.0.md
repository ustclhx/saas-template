## 概要

- **提示词版本与评测（add-prompt-evals）**：`@saas/ai` 新增提示词定义工具，新增只供命令行使用的评测包 `packages/evals` 与根脚本
  `pnpm eval:prompts --suite <name>`：固定样本、多个提示词版本、默认离线回放、可选真实模型（必须给美元预算上限）、确定性检查、
  LLM 评委、报告与基线对比。完整说明见 [AI §3「提示词版本与评测」](../06-ai.md#提示词版本与评测add-prompt-evals)。
- 提示词评测部分同步后没有运行时行为变化：没有迁移、没有部署变化，`packages/evals` 不进入任何 Worker 或自托管产物。
- **对话组件（add-ai-chat-components）**：对话页与嵌入式 SubjectChat 改用 `@<scope>/ui/chat` 组件（Markdown 回复、推理折叠、工具卡片、
  停止 / 失败 / 未完成状态、状态播报），SubjectChat 改为 `EmbeddedChat` 外壳；**不兼容**：删除 `ChatPage` 的 `variant="embedded"`，
  新增项目自有文件 `message-parts.project.tsx`。详见下方小节。

- **分享卡片韩文与运行时语言（add-share-card-project-overrides 跟进）**：底部副标题不再被裁掉半个字；韩文标题与摘要按词换行；
  多语言多站点项目的运行时卡片按分享页语言显示品牌。没有站点覆盖的项目卡片地址不变，渲染结果只在原先会被裁切的副标题上变化。

### 对话组件（add-ai-chat-components）

- **对话页外观**（设计稿 `docs/design-system/prototypes/chat-components/Main.dc.html`、`Mobile.dc.html`）：720px 居中消息列，
  标题行（「全部对话」返回、标题、对话操作菜单：新对话 / 归档）留在对话区头部、不进顶部条；输入区吸附在视口底部（短对话与空态也贴底，
  `apps/web/src/styles/app.css` 新增 `min-h-chat-page` 工具类）；回复按 Markdown 渲染（表格、代码块带语言名与复制），
  操作区为复制回复、评分与「N 积分 · 模型」（只对刷新后的历史回复显示，`getConversation` 的消息多返回 `credits`、`modelKey`）；
  生成中上翻时出现「回到最新」；错误与余额不足提示移到输入框上方，被拒的消息放回草稿。路由新增加载骨架（`ChatPageSkeleton`）。
- **SubjectChat 外观**（`Embedded.dc.html`、`EmbeddedMobile.dc.html`）：改为渲染 `@<scope>/ui` 的 `EmbeddedChat` 外壳——
  对象标签为徽标、对象标题为标题，头部为历史对话菜单（第一项「新对话」）与新对话按钮（手机抽屉里只在菜单中）；还没有对话时的推荐问题
  与输入框也在外壳内。新增可选属性 `variant`（`'inline'` 默认 / `'panel'`）、`open`、`onOpenChange`、`showTrigger`：
  ≥ 768px 时 inline 为正文中的卡片（最高 420px、消息在卡片内滚动），panel 为悬浮按钮 + 右侧面板；< 768px 都是悬浮按钮 + 底部抽屉。
  **以前在页面流中直接显示的对话，手机上改为悬浮按钮**。对话状态按会话保存在外壳之外：关闭面板 / 抽屉不停止生成，再打开时消息与草稿都在。
  `SubjectChatView` 的 `onSelectConversation` 改为 `loadConversation(id): Promise<SubjectChatData>`，`className` 等外壳属性同 SubjectChat。
- **不兼容：`ChatPage` 的 `variant="embedded"` 与 `autoSend` 删除**。嵌入其他页面的对话改用 `<SubjectChat slug subjectType subjectId />`；
  需要自建布局时用同一组组件：
  ```tsx
  const [session] = useState(() => new ChatSession({ slug, conversationId, title, storedMessages, models, readOnly }))
  useEffect(() => () => session.dispose(), [session])
  <ChatThread session={session} />                                  // features/ai/chat-thread.tsx
  <ChatComposer session={session} placeholder={m.chat_ui_placeholder()} /> // features/ai/chat-composer.tsx
  ```
  `chat-page.tsx` 不再导出 `InsufficientCreditsGuide`（余额不足提示在 `ChatComposer` 内）。`chat-extras.tsx` 的 `MessageFeedback`
  新增可选 `actions` / `meta`，`CreditsDialog` 新增可选 `fallbackFocus`；`ModelPicker` 新增 `compact`。
- **文案与 id**：模型选择与预计消耗（`MODEL_PICKER_COPY` 改为按语言读取的 getter，`formatEstimate` 输出按语言）、对话不存在页与对话页标题回退
  都进 `ai-chat-ui.json`；`conversation.ts` 删除未使用的 `CHAT_ERROR_FALLBACK`（用 `m.chat_error_unknown()`）。输入框与模型选择的 id 改为
  `useId` 生成，项目 e2e 若用 `#chat-input` / `#ai-model` 定位，改为 `[data-input-message] textarea` / `[data-model-picker] [role="combobox"]`
  或可读名称。对话页路由声明 `staticData: { shellTitle: false }`，侧边栏布局顶部条在该页不显示标题。
- **新子路径 `@<scope>/ui/chat`** 由对话页与 SubjectChat 使用（对话组件不进主入口与首页包）；`@<scope>/ui/icons` 新增
  `Archive`、`ArrowDown`、`Copy`、`History`、`Sparkle`、`SquarePen`。
- **新增项目自有文件** `apps/web/src/features/ai/message-parts.project.tsx`（导出空的 `registerProjectToolRenderers()`）：
  用 `registerToolRenderer(toolName, { label, render? })`（`features/ai/tool-renderers.ts`）登记工具卡片的显示名与可折叠详情；
  未登记的工具只显示「工具」与状态，不显示内部名称、参数与结果。生成、同步与发版检查规则与 `share-cards.fonts.ts` 相同。
  适配层 `features/ai/message-parts.tsx` 为模板拥有。
- **回复图片不再显示**：Markdown 图片只显示替代文字（防止图片地址外泄对话内容）；`javascript:` / `data:` 链接显示为文字，原始 HTML 丢弃。
  以前以纯文本显示的历史回复现在按 Markdown 渲染。
- **文案**：对话页与 SubjectChat 的文字全部在 `messages/<locale>/ai-chat-ui.json`（新增 `chat_ui_*` 键）；只启用了 en / zh 以外语言的项目
  需补译这些键。对话页中「Stop」的中文为「停止生成」；e2e 依赖英文名称（Messages / You / Assistant / Send / Stop / Stopped / All chats）的不变。
- **指纹变化**：`reader-markdown.tsx`（与 `ChatMarkdown` 共用的 Markdown 选项抽到 `lib/markdown.ts`，阅读器渲染不变）；`embedded-chat.tsx`（标题栏改为徽标 + 标题 + 操作 + 关闭、去掉 inline 卡片头像，inline 卡片最高 420px 且消息区滚动、
  输入区上边线分隔，侧面板宽 420px，手机抽屉固定 86% 视口高）。改过对话页或 SubjectChat 的项目按冲突逐处合并，项目对外观的定制按
  `docs/design-system.md` §9.2 的顺序改到 token 或 project 包装中。
- **首页包检查**：对话 Markdown 的标记已在 `check-home-bundle.mjs` 拦截；首页不得静态导入 `@<scope>/ui/chat` 或 `features/ai/chat-*`。
- **e2e**：新增 `e2e/chat-ui.spec.ts`（默认配置）与 `e2e/subject-chat.spec.ts`（`pnpm --filter @<scope>/web exec playwright test -c playwright.subject-chat.config.ts`，
  用 `e2e/subject-chat/vite.ts` 登记测试对象类型）；对话 e2e 的共用夹具移到 `e2e/chat-fixtures.ts`。

- 组件预览页新增 `/dev/ui#chat`（对话组件各状态、Markdown 安全处理、流式模拟），可作为衍生项目对话外观的对照；
  原 EmbeddedChat 预览的消息与输入区改用 `ChatMessage` / `InputMessage`。`ToolCall` 「已完成」徽标浅色底色由 10% 改为 6%
  （axe color-contrast）；`ChatMarkdown` 代码块与表格的滚动容器由带名称的 `<section>`（region 地标）改为
  `role="group"`（axe landmark-unique）；`InputMessage` 的查询容器移到内层 `[data-input-message-body]`，根节点加
  `w-full min-w-0`（在 flex-wrap 父级中高度不再被撑大）。`tool-call.tsx`、`chat-markdown.tsx`、`input-message.tsx` 指纹变化。

### 分享卡片韩文与运行时语言

- **副标题裁切**（xuanxue 反馈：「간지데이 · 무료 만세력·사주·타로」只显示半个「로」）：不是截断造成的。satori 测量时 `·`、空格用 Inter，
  绘制时同一词段用段首字符的字体（谚文段用项目字体、汉字段用 Noto Sans SC，`·` 更宽），副标题盒宽等于测量宽度，`overflow: hidden`
  把多出的部分裁掉。中文副标题里不带空格的 `·`（如「免费万年历·八字·塔罗」）同样受影响。现在副标题盒子占满域名左侧的剩余宽度，
  上限随域名宽度收紧（`metaLimit`），仍超出时 satori 在字素边界加省略号。纯拉丁与没有该差异的卡片像素不变（已用模板字体比对 PNG 字节）。
- **韩文换行**：标题与摘要含谚文且不含汉字、假名时设置 `wordBreak: 'keep-all'`，在空格处换行（不再出现「개 / 인정보」）；
  `countLines` 新增第三个参数 `keepAll`（默认按新导出的 `keepsWords(text)` 判断），截断仍保证两行内。中日文与拉丁标题的版式不变。
  项目自建版式显示韩文段落时同样设置 `keep-all`。
- **运行时语言**：通用分享页与 `shareCardMeta` 把页面语言作为 `context.locale` 传给 `resolveProjectShareCardSite`；
  站点覆盖生效且语言不是默认语言时，卡片地址追加 `&l=<locale>` 并计入 `v`。卡片路由与 `/dev/ui` 预览只接受 `template.config.ts`
  启用的语言，缺省或未知值按默认语言。默认语言、以及没有站点覆盖的项目地址不变（已发出的卡片地址继续有效）。
  `resolveRequestShareCardSite` 新增可选的第四个参数 `locale`。
- 运行时 `context.locale` 现在总有值（缺省为默认语言），此前卡片路由传入 `undefined`。解析函数若以 `locale === undefined` 判断默认语言，
  改为与默认语言比较。

### 提示词版本与评测（add-prompt-evals）

- **`@<scope>/ai` 新导出**（`text/prompt.ts`，业务无关、无新依赖）：`definePrompt`、`renderPrompt`、`promptCanonicalJson`、`promptSha256`、
  `renderedPromptDigest` 与类型 `PromptDefinition`、`DefinedPrompt`、`PromptSection`、`PromptParams`、`RenderedPrompt`、`RenderedSection`。
  `definePrompt` 返回带 `promptVersion`（`<id>@<version>`）的冻结定义。
- **新包 `@<scope>/evals`**（私有，依赖 `@<scope>/ai`、`ai`、`zod`）：套件与版本锁、内置检查（章节、长度、禁用词与正则、文字占比、简繁误用）、
  美元预算账本、LLM 评委、回放 / 真实 / 录制三种模式、报告与基线、命令行入口；自带示例套件 `packages/evals/example/`。
  包单测（示例套件离线回放）随 `pnpm test` 运行，不发出真实调用。
- **根 `package.json`**：新增脚本 `eval:prompts`（`node --experimental-strip-types packages/evals/src/cli.ts`，存在时由入口加载根目录 `.env.local`）
  与开发依赖 `@<scope>/evals: workspace:*`。该脚本不在 turbo 任何任务中；`CI` 为真时拒绝 `--live` / `--record`，且版本锁冻结（缺条目即配置错误）。
- **依赖检查**：`pnpm check:deps` 新增规则——除根 `package.json` 外，任何 app 或 package 的 manifest 与源码（含测试）都不得依赖或引用 `@<scope>/evals`。
- **项目自有目录 `evals/`**：项目套件放在根目录 `evals/<suite>/`。模板永远不在该目录交付文件（模板侧 `template-release check` 会拒绝），
  `template-sync` 因此不会新增、覆盖或删除其中的文件。
- **报告位置**：`$EVIDENCE_DIR/prompt-evals/<suite>/…`，未设置时为已被 `.gitignore` 忽略的 `test-results/evidence/`，不进仓库。

## 配置变更

- 根 `package.json` 新增脚本 `eval:prompts` 与开发依赖 `@<scope>/evals`；项目改过根 `package.json` 时合并这两处，然后 `pnpm install` 更新锁文件。
- 新增目录 `packages/evals/`（模板拥有，同步时正常更新）。项目自己的套件不要放进该目录，放在根目录 `evals/<suite>/`。
- 真实或录制模式使用与线上相同的文本模型出口变量（`AI_TEXT_EGRESS`、`OPENAI_BASE_URL`、`AI_GATEWAY_ACCOUNT_ID`、`AI_GATEWAY_ID`、
  `AI_GATEWAY_TOKEN` 与各服务商 API key 的名称），从本地 `.env.local` 读取；没有新增必填变量或密钥。
- **衍生项目接入（可选）**：
  1. 用 `definePrompt` 在功能目录定义提示词（模块保持纯函数、只用可类型剥离的 TS 语法），生成时用 `renderPrompt`；
  2. 在项目自有的生成表加列 `prompt_version text not null`，写入 `promptVersion`，结构化日志同时记录该字段（模板的 `ai_message` 不加此列）；
  3. 建 `evals/<suite>/suite.ts`、`samples.json`（只放合成或脱敏数据），模型声明美元单价；
  4. 先 `pnpm eval:prompts --suite <suite> --record --budget-usd <美元>` 录制一次并提交录制与 `prompts.lock.json`，
     之后改提示词时新建版本，用 `--baseline <旧版本>` 离线回放对比。

回退代码即可：删除 `packages/evals`、根 `package.json` 的 `eval:prompts` 脚本与 `@<scope>/evals` 开发依赖，以及 `packages/ai/src/text/prompt.ts` 的导出。

## 已知问题

- 示例套件的回放录制目前是按格式手写的（`source: "constructed"`），用于离线验证工具本身，不代表真实模型的输出质量；真实录制待补。
- 简繁检查只覆盖约 500 个常用「仅繁体」字及对应简体字，罕见字可能漏检；需要更严格的判定时用自定义检查替换。
- 分享卡片：satori 用段首字体绘制整段的差异同样存在于标题与摘要（satori 按测量宽度换行），某行恰好排满且含多个 `·` 等标点时，行尾可能比内容区右缘多出几像素而被标题盒裁掉；验收样例中未出现。根治需要 satori 按绘制字体测量，待上游。
