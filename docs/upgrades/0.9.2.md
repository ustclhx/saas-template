## 概要

- 已完成同步的衍生项目可以指定原来的 `--branch`，在同一分支继续同步到更新的模板目标。工具会核对同步记录和分支历史，拒绝包含无关提交的分支以及等于或早于记录的目标。
- 后台 API 令牌页移除路由专属加载骨架，避免它随公共路由树进入首页水合闭包。后台布局统一显示加载提示，令牌页保留设计稿的空态、失败提示和重试按钮。
- 自 0.9.1 起已合入后台敏感操作重新验证、MCP 待确认记录和 Cloudflare 部署资源解析的基础实现。[MCP 工具与权限](../admin-mcp.md#工具与权限) · [部署资源解析](../07-infrastructure.md#部署资源自动解析cloudflare)
- **公开页面优先的项目扩展点**：0.9.1 起 Worker 在环境校验失败时也先返回命中的预渲染静态资源，这一步早于所有闸门，会绕过衍生项目写在 `server.ts` 里的站点规则（多站点按 Host 选预渲染目录、非本站语言前缀 404、默认语言前缀 301、静态页 CSP 与站点 favicon）。这些规则改放在项目自有文件中，template-sync 更新 `server.ts` 与 `__root.tsx` 时不再与项目改动冲突。未改动这两个文件的项目行为不变。[项目自有扩展文件](../02-project-structure.md#项目自有扩展文件)
  - 新增项目自有文件 `apps/web/src/server/project-gate.ts`（首次交付后 template-sync 不覆盖）。`gateProjectRequest(request, { env, envValid })` 在预渲染静态资源之前调用，环境校验失败时同样先调用。返回 `Response` 直接响应（按静态响应补安全头，HTML 按内联脚本哈希补 CSP）；返回 `Request` 作为查找静态资源的改写请求，未命中时动态流程仍用原始请求；返回 `undefined` 不处理（模板默认）。
  - 同一文件的 `staticFirst`（默认 `true`）为 `false` 时恢复 0.9.0 行为：环境校验失败时静态页也返回 500。插件 `worker.fetch` 仍晚于静态资源。
  - 新增项目自有文件 `apps/web/src/features/app-shell/root-fallbacks.project.tsx`，导出 `RootNotFound`、`RootError`（默认是模板的 `NotFoundPage` / `ErrorPage`）。`__root.tsx` 的 404 / 错误组件与 `router.tsx` 的默认组件都从该文件取，分享页错误界面随之使用项目组件。
  - template-sync 的 `projectOwnedPaths` 补登 `apps/web/src/features/app-shell/nav.project.ts`（此前只在发版检查中登记），同步不再覆盖项目的导航登记。

### 已有项目如何把自有闸门迁到钩子

适用于在 `apps/web/src/server.ts` 里自行加了站点 / 语言闸门，或在 `routes/__root.tsx` 里换了 404 / 错误组件的项目。

1. 同步时 `server.ts` 以模板版本为准解决冲突，再把「静态资源之前」的规则搬进 `project-gate.ts` 的 `gateProjectRequest`：
   - 站点闸门的拒绝、重定向（如默认语言前缀 301）、本站风格 404 → 返回 `Response`；
   - 按 Host 选预渲染目录 → 返回改写路径后的 `new Request(url, request)`，由模板查 `ASSETS`；
   - 站点 favicon → 对 `/favicon.ico` 返回改写后的请求（或直接 `env.ASSETS.fetch` 的结果）。
   静态页的 CSP 补头由模板统一处理（钩子返回的响应与命中的静态资源都经 `withStaticSecurityHeaders`），删除项目自己的补头代码。
2. 只与动态请求有关的闸门（公开 API、后台、语言 Cookie 等）仍用模板入口的既有闸门或插件 `worker.fetch`；钩子运行在环境校验与运行时之前，不要查库或读会话。
3. 暂时不能迁移、又必须保证闸门先于静态页时，先在 `project-gate.ts` 设 `staticFirst = false`：环境校验失败时公开页也返回 500，但校验通过时行为同 0.9.0。迁移完成后改回 `true`。
4. `__root.tsx` 以模板版本为准解决冲突，把项目品牌的 404 / 错误组件从 `root-fallbacks.project.tsx` 导出为 `RootNotFound` / `RootError`。根路由出错时模板仍会补上 HTML 外壳（`RootDocument`），项目组件只渲染页面主体。

## 验证

- 在衍生项目的既有同步分支上，用目标版本的同步脚本指定原 `--branch` 和更高的 `--to`，确认成功后基准记录指向新目标。已有无关提交时，另开同步分支。
- 运行 `pnpm build`，查看首页水合闭包的 gzip 体积。打开后台 API 令牌页，核对空列表，以及加载失败时的提示和重试操作。
- 迁移了闸门的多站点项目部署 staging 后，分别用两个站点的 Host 请求同一预渲染路径，确认返回各自站点的页面；请求非本站语言前缀与默认语言前缀，确认 404 与 301。暂时缺一项必填密钥的预览环境中，预渲染页仍返回 200（`staticFirst = false` 时为 500）。

## 回滚

回退应用代码。新增数据库表和已有同步记录保留。已把闸门迁到 `project-gate.ts` 的项目，回退前把规则放回 `server.ts`。
