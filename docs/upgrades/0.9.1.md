## 概要

修复衍生项目采纳 0.9.0 时遇到的模板侧问题。没有新增必填配置、密钥、绑定或数据库迁移。

> **升级前先检查每日赠送设置。** 运行时设置读到不符合当前定义的旧值时，不再抛错，而是回落代码默认值（见第 4 项）。
> 每日赠送领取也走这条路径。如果项目曾把 `credits.dailyAmount` 设为 `0` 表示「不发放」，而当前定义的下限是 1，升级后会按默认值发放（模板默认每天 10 积分）。
> 部署前在后台「运行时设置」页查看是否出现「正在使用默认值」的提示，也可以用 MCP `settings.get` 查看 `source` 是否为 `fallback`。
> 不发放每日赠送应关闭模板配置 `credits.dailyEnabled`，而不是把数量设为 0。

1. **测试不再写死应用名与语言**：`plugins/admin-mcp/src/web/api-tokens-page.test.tsx` 由 mock 的应用名推导 MCP 服务名，不再写死 `myapp-admin`。按钮与复选框名称改从 `m.*` 文案取，衍生项目改名或默认语言不是英文时都能通过。
2. **加载骨架移出客户端入口包**：TanStack Router 默认不拆分路由的 `pendingComponent`，从整页模块导入骨架会把整页带进每个页面的入口包。
   - 令牌页的加载与错误状态移到 `plugins/admin-mcp/src/web/api-tokens-states.tsx`。
   - 账单页的 `BillingCard`、`BillingSkeleton` 移到 `apps/web/src/features/billing/billing-skeleton.tsx`；`billing-sections.tsx` 仍重新导出 `BillingCard`。
   - 模板首页的水合闭包 gzip 由 311873 B 降到 289236 B（103 → 94 个脚本）。
3. **只部署 Cloudflare 的项目不再引用 Node 插件入口**：
   - web 的 Node 插件类型 `WebNodePluginModule`、`WebNodePluginRegistration` 从 `apps/web/src/features/plugins/contract.ts` 移到新文件 `apps/web/src/node/plugins.ts`。两目标共用的契约不再导入 `NodeEnv`。
   - `scripts/plugins/plugins.mjs` 只在 `apps/web/src/node/plugins.ts`、`apps/jobs/src/node/plugins.ts` 存在时分别生成 web、jobs 的 `*.node.gen.*`，并删除不再生成的旧文件。
   - 删除 Node 入口的步骤见「配置变更」。
4. **运行时设置读取遇到不合 schema 的旧值时回落默认值**：
   - 读取不再抛 `RangeError`，覆盖 `getSetting`、`getSettingValue` 与每日赠送领取；同时记录结构化告警 `runtime_setting.invalid_stored_value`，只含键名与作用域，不含值。同一 isolate 或进程内每个键只告警一次。
   - 写入仍严格校验：后台保存与 MCP `settings.set` 继续拒绝不合规的值。
   - `@saas/db` 新增 `resolveStoredSetting(key, stored)`，返回 `{ value, source }`，`source` 为 `database`、`default` 或 `fallback`。
   - 后台「运行时设置」页列出正在使用默认值的键；MCP `settings.get` / `settings.list` 的结果增加 `source`，密钥项也返回 `source`，但不返回值。
5. **dev 与 e2e 冷启动先生成文案**：
   - 问题：`src/paraglide` 尚未生成时（CI、新 worktree），Vite 依赖扫描会因 `@web/paraglide/...` 无法解析而跳过预打包，之后按请求逐个发现依赖并反复重载。
   - 修复：i18n 插件在 `vite dev` 的 `config` 阶段发现生成目录缺失时先编译一次。`pnpm dev`、各 Playwright 配置的 webServer 与衍生项目都受益，无需改命令。
   - 效果：本地冷启动到 `/api/health` 可用由 223.6 s 降到 79.6 s，依赖扫描失败 1 次 → 0 次，重新优化与重载 30 次 → 0 次。
6. **令牌页 loader 只导入列表函数**：列表读取移到 `plugins/admin-mcp/src/web/api-tokens-list.functions.ts`，创建与吊销函数不再随路由 loader 进入入口包。
7. **MCP `audit.list` 保留行上的附加字段**：行映射移到 `plugins/admin-mcp/src/web/tools/audit.ts`，只对 `log.meta` 脱敏。项目的 `listAuditLogs` 在行上附加的字段（如多站点项目的 `site`）原样返回。

8. **发版检查**（仅模板仓库）：`scripts/template-release.mjs check` 改为把已交付的项目自有文件与上一发布版本中的内容比较，不再与创建提交比较。此前，在首次发布前修改过的文件（如 0.9.0 的 `plugins/agents/src/agents.project.ts`）会被误报。

另含 0.9.0 之后合并到 main 的改动，均无迁移与模板配置变更：

- **管理员 MCP 工具参数说明**（#485）：补齐全部工具参数说明，并校验工具文档与实现一致。
- **公开页面优先**（#488，add-ops-safeguards）：
  - 预渲染与插件绑定故障互相隔离，语言降级。
  - 新增兜底错误界面。
  - 公告与模拟登录读取失败时按无公告、无模拟处理并记录告警；公告设置值不合规时按第 4 项回落默认值，同样不显示公告。
- **R2 / KV 临时错误重试**（#489，add-ops-safeguards 第 4 组）：写入与删除遇到临时错误时有限次重试，见 [平台能力](../platform-capabilities.md)。
- **第三方登记表与守卫**（#486，add-ops-safeguards 3.1–3.4）：
  - `pnpm check` 新增 `scripts/check-third-party.mjs`：受监视的第三方 SDK 依赖必须在 `scripts/third-party-deps.json` 中映射到 [第三方登记表](../third-party.md) 的一行。
  - 已核对 xuanxue 与 product-res 的现有依赖都已登记。项目以后新增受监视的 SDK（如新的 `@ai-sdk/*` Provider）时，需同时登记。
- **文档与规划**（#481–#483、#487）：OpenSpec change 规划与设计稿登记，不影响运行时。

## 配置变更

- 没有新增或删除的模板配置键。
- 项目自有插件如果从 `@web/features/plugins/contract.ts` 导入 `WebNodePluginModule` 或 `WebNodePluginRegistration`，改为从 `@web/node/plugins.ts` 导入。模板自带插件已更新，已知衍生项目都没有这样的导入。
- 新增 web 文案键 `admin_settings_using_defaults`（`apps/web/messages/<locale>/admin.json`），带参数 `{keys}`。项目新增了其他语言时，补上该语言的翻译；缺少时运行时回退到默认语言。
- **只部署 Cloudflare、要删除 Node 入口的项目**（可选）：
  1. 删除 `apps/web/src/node/plugins.ts` 与 `apps/jobs/src/node/plugins.ts`，以及项目不再使用的 Node 入口：`apps/web/src/server.node.ts`、`apps/web/src/node/` 下的 Node 服务文件、`apps/jobs/src/index.node.ts`、`apps/jobs/src/node/`、`packages/config/src/node*.ts`、`packages/platform/src/node/`，并删除对应 `package.json` 中的 `./node` exports。分享卡片渲染器等两目标共用的文件保留。
  2. 运行 `node scripts/plugins/generate.mjs`。生成器不再写出 `*.node.gen.*`，并删除之前生成的旧文件。
  3. 撤掉为绕开 0.9.0 问题所做的临时改动：`apps/jobs/tsconfig.json` 对 `src/plugins.node.gen.ts` 的 `exclude`，以及为去掉 `NodeEnv` 在 `contract.ts` 中放宽的 `env` 类型（同步后该文件已不含 Node 类型）。
  4. 处理仍引用已删除文件的测试，例如 `apps/web/src/server/cloudflare/security-entry.test.ts` 中对 `server.node.ts` 的导入，然后运行 `pnpm typecheck`。

## 部署顺序

1. 部署前在目标环境的后台「运行时设置」页检查有没有「正在使用默认值」的提示，或用 MCP `settings.list` 查找 `source: "fallback"` 的键。
   - 对每个这样的键，确认默认值符合预期；不符合时先保存合法的值。
   - 尤其是 `credits.dailyAmount` 等每日赠送参数：如果曾用 `0` 表示不发放，改为关闭模板配置 `credits.dailyEnabled`，否则升级后会按默认值发放。
2. 按常规流程部署 web 与 jobs。没有迁移，也没有先后约束。

pnpm check:deps
pnpm test
pnpm build
pnpm build:node            # 支持 Node 目标的项目
pnpm test:create-project   # 模板仓库

- 冷启动：删除 `apps/web/src/paraglide` 与 `apps/web/node_modules/.vite` 后启动 `pnpm dev`，日志中不应出现 `Failed to run dependency scan` 或连续的 `optimized dependencies changed. reloading`。
- 后台「运行时设置」页：没有回落键时不显示提示。
- 多站点项目：调用 MCP `audit.list`，返回行中应有 `site` 字段。

## 回滚

回退本版本代码即可，不涉及数据库或配置。

回滚后，数据库中不合规的设置值会恢复为读取时抛错。回滚前先保存合法的值；已经删除 Node 入口的 Cloudflare 项目回到 0.9.0 后，需要重新采用 0.9.0 的临时绕过改动。
