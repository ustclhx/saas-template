## 概要

这一版的主要变化：

- **埋点、首触归因与发布串扰门禁**（`add-analytics-plausible-geo`）：
  - 统一的事件字典；
  - 服务端权威事件 `sign_up`、`payment_success`；
  - 第一方首触 Cookie，注册时写入 `user_attribution`；
  - 默认接入自建 Plausible；
  - 部署后检查 sitemap、canonical 与分析脚本的站点归属。
- **SEO/GEO 骨架**：`llms.txt`、IndexNow 提交、可选答案页 `/guides`（`features.guides`）、定价页转化路径、404 页可回到导航、法律页不再出现模板占位邮箱。
- **Plausible 多站**（`add-plausible-multi-site`）：一个部署按访问域名服务多个站点时，可以用 `PLAUSIBLE_SITES` 为每个访问域名指定 site。页面事件按当前访问域名上报，服务端事件按注册时的访问域名上报。未配置时与单站行为相同。
- **修复**：
  - selfhost 透传 `PAYMENT_MODE`，空值按未设置处理；
  - template-sync：模板删除的文件只提示不删除，移植后格式化迁移 meta，修正已发布迁移的判定。
- **生产 Cron 档位检查**：`check-wrangler-envs` 要求生产 jobs 显式声明 `CRON_PROFILE`，并且与 triggers 一致。Neon 成本基线见 `docs/runbooks/production-neon.md` §4。

## 必须执行的动作

无

## 配置变更

- `features.analytics` 的默认值由 `false` 改为 `'plausible'`。`template.config.ts` 新增 `features.analytics` 与 `features.guides` 两行。
  - template-sync 会按项目的基准参数生成：没有 `guides` 参数的旧项目，`guides` 为 `false`，不会出现示例答案页。
  - 已显式写 `features.analytics: 'posthog'` 的项目保留原设置；同步后确认 features 里只有一个 `analytics` 键。
- 只要 `features.analytics` 不为 `false`，首触归因就会开启：浏览器写第一方 Cookie `saas_ft`（180 天），注册时写入 `user_attribution`。即使没有配置 Plausible 也是这样。
  - 访客设置了 DNT 或 GPC 时不写 Cookie。
  - 隐私政策模板已说明这个 Cookie。
  - 不需要首触归因的项目，把 `features.analytics` 设为 `false`。
- 新增非敏感变量 `PLAUSIBLE_DOMAIN`、`PLAUSIBLE_HOST`、`PLAUSIBLE_SITES`，写在 web 与 jobs 的 wrangler `vars`（两者须一致）或 selfhost `.env`。
  - 任一为空时不注入脚本，也不发送服务端事件。
  - 预渲染页面读 `template.config.ts` 的 `analytics.plausibleDomain`、`plausibleHost`、`plausibleSites`。
  - 开站与多站配置见 `docs/analytics.md` §4。
- jobs 的 wrangler 各环境新增 `APP_URL`，用作服务端事件的 URL。同步时取项目自己的地址；手工维护的配置需要与 web 的 `APP_URL` 一致。
- 新增可选 secret `INDEXNOW_KEY`：GitHub `production` environment secret，selfhost 写在 `.env`。未配置时跳过提交。
- selfhost：
  - `compose.yaml` 透传 `PLAUSIBLE_DOMAIN`、`PLAUSIBLE_HOST`、`PLAUSIBLE_SITES`、`INDEXNOW_KEY`、`PAYMENT_MODE`，`.env.example` 同步新增这几项。
  - 开启 billing 的 selfhost 项目需要在 `.env` 设置 `PAYMENT_MODE`（`test` 或 `live`）。之前这个变量不会传进容器，所以支付一直不可用。
- 发布流水线：
  - `deploy-staging.yml` 与 `deploy-production.yml` 在部署后运行 `scripts/staging/check-site-isolation.mjs`：sitemap、canonical 必须指向本环境的 `APP_URL`，分析脚本的 site 必须与本环境配置一致。
  - 生产发布后提交 IndexNow。
- `pnpm check`（`check-wrangler-envs`）新增几项拒绝条件：
  - staging 与生产共用 `APP_URL`、`PLAUSIBLE_DOMAIN`，或站点映射中的同一个 site；
  - web 与 jobs 的站点变量不一致；
  - 站点映射无法解析；
  - 生产 jobs 的 `CRON_PROFILE` 与 triggers 不匹配。
- CSP 放行 `PLAUSIBLE_HOST` 这一个实例地址。
- Worker secrets、`packages/config` 的必填环境校验、支付 webhook 订阅事件都没有变化。

## 数据库变更

### 0019_user_attribution

- 类别：扩展
- 兼容上一版本代码：是
- 锁表与耗时：只新建表 `analytics_delivery`、`user_attribution`，以及指向 `user` 的外键（新表为空，校验瞬间完成），可以忽略；迁移设置了 `lock_timeout=5s`、`statement_timeout=30s`
- 回滚：只回退代码，保留新表

`user_attribution` 每个用户一行，保存首触归因，随账号删除级联清除。`analytics_delivery` 记录已发送的服务端分析事件，用于去重。

### 0020_user_attribution_signup_host

- 类别：扩展
- 兼容上一版本代码：是
- 锁表与耗时：`user_attribution` 新增可空列，只改元数据，可以忽略；迁移设置了 `lock_timeout=5s`、`statement_timeout=30s`
- 回滚：只回退代码，保留新列

`signup_host` 记录注册时规范化后的访问域名，多站时用来判断付款事件归属哪个 site。不回填老用户。

## 回滚

0019、0020 都带 `-- rollback-safe:` 注释，可以回退到 0.2.0 的代码，schema 保持不变：

- Cloudflare：`gh workflow run deploy-production.yml --ref main -f tag=<旧 tag>`；
- selfhost：用旧 SHA 的 release bundle 部署。

想关闭新功能而不回退代码：

- 清空 `PLAUSIBLE_*` 即停止上报，首触归因仍会写库；
- 设 `features.analytics: false` 会同时关闭首触归因；
- 删除 `PLAUSIBLE_SITES` 即退回单站。

## 已知问题

- Plausible 社区版没有漏斗和收入目标，`payment_success` 的 revenue 字段会被丢弃。看流失时对比各目标的转化数；金额用 `docs/analytics.md` §3 的 SQL。
- 多站部署时，部署后检查要求被检查地址的 origin 等于 `APP_URL`，所以只能校验主域名，其他访问域名暂时不在门禁内。
- Cloudflare Rate Limiting 绑定在线上 Worker 中总是放行（workers-sdk#16097），与 0.2.0 相同。
