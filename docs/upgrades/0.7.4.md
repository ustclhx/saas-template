## 概要

修复 0.7.3 站内链接规范在衍生项目（多站点、URL 前缀与语言 id 不同、没有 `zh` 语言）中的问题，并补上通用的多站点支持。单站点项目的输出与检查结果不变。

- **链接图检查的语言首页**：按路由的实际前缀（Paraglide 运行时 `localizeUrl`）抓取，不再拼接 `/<语言 id>`；项目把前缀改成小写等写法时不再误报死链。钱页入链统计同样按实际前缀去掉语言段。
- **多站点**（新配置 `seo.linking.sites`，默认为空）：按站点分组语言。
  - 回退页只在原语言与页面语言属于同一站点时 canonical 指向原语言；原语言在另一站点时按普通页面处理，不输出跨站 canonical。判断函数为 `metadata.ts` 的 `fallbackSourceLocale()`／`sameSiteLocales()`。
  - 声明了 `previewHost` 的站点在链接图检查中各自成图：以 Host 请求头访问 preview，不依赖 DNS 解析 `*.localhost`；其他站点的主页与链接不再混入同一张图。
- **检查用的 `.dev.vars`**：缓存命中缺少 `dist/server/.dev.vars` 时，补写的文件会把示例中值为空的 `*_SECRET`／`*_TOKEN` 随机生成，并叠加本地 `apps/web/.dev.vars`。项目自有的 Worker 必填变量写进 `.dev.vars.example` 即可，preview 不再因缺变量返回 500。
- **重命名**：`structured-data.ts` 的 `breadcrumbData()` 改名为 `breadcrumbListData()`，避免与衍生项目自有的同名函数冲突；模板路由已全部改用新名。
- **测试**：`check-links-graph.test.ts` 的站点主机由完整 URL 推出，create-project 改域名后仍一致；`template.test.ts` 的多语言文案用例显式传入夹具语言；`scripts/content.test.ts` 按仓库实际的博客源文件断言草稿与内链字段，不再依赖示例文章。`linking.test.ts`、`page-links.test.ts` 的另一语言与地址前缀按项目配置推出，默认语言为 zh 或关闭多语言的生成项目也能通过。

## 配置变更

- 可选：多站点项目在 `template.config.ts` 设 `seo: { linking: { sites: [{ locales: [...], previewHost: '...' }] } }`，字段说明见 [站内链接规范 §7](../seo-internal-linking.md#7-多站点)。不配置时行为与 0.7.3 相同。
- 0.7.3 新增的 `breadcrumbData()` 改名为 `breadcrumbListData()`，参数与返回值不变。模板路由随同步自动更新；只有项目自有代码调用过模板的这个函数时才需要改名，类型检查会指出位置。
