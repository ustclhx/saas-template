## 概要

- **运行时分享卡片（add-og-images）**：衍生项目注册「卡片类型」（解析函数、摘要、版式、替代文本、分享页标题与描述）后，
  得到按需渲染的 1200×630 结果卡片 `/share-card/<类型>/<令牌>.png` 与通用分享页 `/s/<类型>/<令牌>`。
  访问控制归项目：模板不建分享表，只按项目的解析结果渲染，并统一执行到期（默认 90 天）、失效、缓存、限流与 `noindex`。
  完整说明见 [分享卡片与分享页](../share-cards.md)。
- 没有注册任何卡片类型的项目没有行为变化：两条新路由对所有请求返回 404。
- 构建期默认分享图（`dist/client/og/`）改用与运行时卡片相同的默认版式：从写死的深蓝渐变改为主题 token 版式
  （设计稿 `docs/design-system/prototypes/share-cards/Card.dc.html` 的 `default` 变体），重新部署后各公开页面的分享图外观变化。
- 删空间（含删号时的个人空间）的清理范围增加该空间已生成的分享卡片图片。
- 需要 **Workers 付费版**：渲染器使 web Worker 整包 gzip 约 3.5 MiB，超过免费版 3 MiB 上限。

### 新增路由与对象存储前缀

- `GET /share-card/<type>/<token>.png?v=<version>-<digest8>`：卡片图片。缓存命中（Cache API 或 R2）时不调用项目解析、不查库；
  浏览器与公共缓存最长 1 天且不超过剩余有效期。
- `GET /s/<type>/<token>`：通用分享页，边缘缓存最多 5 分钟，`noindex`；项目可按类型 `sharePage: false` 关闭并自建页面，
  用 `shareCardMeta` 输出同一套元数据。
- `GET /api/dev/share-card-preview`、`POST /api/dev/share-cards`：`/dev/ui` 预览与 e2e / staging 验收夹具，只在 `UI_PREVIEW=true` 时可用，
  夹具另需平台管理员会话；生产 404。
- `robots.txt` 新增 `Allow: /share-card/` 与 `Allow: /s/`（含各语言前缀）；两者不进站点地图与 `llms.txt`。
- 现有 `FILES` 桶新增前缀 `share-cards/`：`img/`（卡片图片，元数据记到期时间与空间）、`ws/`（空间索引，删空间清理用）、
  `revoked/`（撤销墓碑，永不删除）。**不要**为该前缀配置生命周期自动过期。KV `CACHE` 新增键 `share-revoked:*`（1 天 TTL）
  与 staging 验收夹具的 `share-sample:*`（1 天 TTL）。

## 必须执行的动作

1. 在 `apps/web/wrangler.jsonc` 的顶层（开发）、`env.staging` 与 `env.production` 的 `ratelimits` 中各声明一次 `RL_SHARE_CARD`（`simple: { limit: 30, period: 60 }`），`namespace_id` 在账号内不得与其他限流绑定或其他环境重复（`pnpm check` 中的 `check-wrangler-envs` 会检查）。项目改过 wrangler 配置导致同步冲突时，按模板的三处新增行手动合并。（适用：target=cloudflare）
2. 确认 Cloudflare 账号为 Workers 付费版后再部署 web；免费版会因脚本超过 3 MiB 而部署失败。部署前可在 `apps/web` 执行 `pnpm exec wrangler deploy --dry-run --outdir <临时目录>` 查看 gzip 体积。（适用：target=cloudflare）
3. 项目改过旧的构建期分享图时（`apps/web/src/features/seo/og-card.ts` 或 `apps/web/scripts/seo/` 下的字体）：同步会在这些已删除或已移动的文件上冲突。处理方法：接受删除 `og-card.ts`，把自定义的配色改写到项目自有的 `apps/web/src/features/share-cards/share-cards.theme.ts`（见下文「主题覆盖」），版式结构差异按 `features/share-cards/layout.tsx` 的 `defaultShareCardLayout` 重新实现并经 `ui-design` 确认；`apps/web/scripts/seo/NotoSansSC-Regular.otf` 与 `FONT-LICENSE` 接受移动到 `apps/web/public/fonts/share-card/`（许可证改名 `NOTO-LICENSE`），项目换过字体时把文件放到新目录并保持文件名 `NotoSansSC-Regular.otf`，或同步修改 `features/share-cards/renderer.ts` 的 `CJK_FONT_FILE`。没有改过这些文件的项目无需处理。

## 配置变更

- **`template.config.ts`**：新增 `shareCards: { defaultTtlDays: 90 }`，分享的默认有效天数；`null` 表示永不过期，其他值必须是正整数。项目改过 `template.config.ts` 时合并这一段（缺省时取模板默认值 90）。
- **项目自有文件**（模板只创建、之后不再修改；`template-sync` 只在文件不存在时新增，不覆盖项目内容；生成器逐字节复制）：
  - `apps/web/src/features/share-cards/share-cards.project.ts`：在 `registerProjectShareCards()` 中登记项目的卡片类型；
  - `apps/web/src/features/share-cards/share-cards.theme.ts`：分享卡片的品牌覆盖 `projectShareCardTheme`，与 `brand.css` 对应。
  模板侧 `template-release check` 会拒绝修改这两个文件的模板提交。
- **主题覆盖与 check-ui**：`share-cards.theme.ts` 填写颜色字面量时，按约定在项目的 `scripts/check-ui.allow.local.json` 为该文件登记 `color-literal` 例外，原因写「分享卡片在服务端渲染，无法读取 CSS 变量」（当前 `check:ui` 只扫描 `.tsx`，不登记也不会失败）。模板的 `scripts/check-ui.allow.json` 删除了 `apps/web/src/features/seo/og-card.ts` 的例外。卡片版式 `.tsx` 仍受 `check:ui` 检查，只能使用 `theme` 提供的值。
- **`@<scope>/ui`**：新增导出 `@<scope>/ui/share-card-theme`（`shareCardThemes` 与 `ShareCardTheme`，与 `tokens.css` 基线一致，由单测保证）。
- **平台能力**：`RateLimiter.limit` 新增 policy `shareCard`；Node 缓存适配器的默认策略增加 `shareCard`（每 60 秒 30 次），可经 `policies.shareCard` 调整。`WebRuntime` 新增 `shareCardRenderer` 与 `shareCardCache` 能力（Cloudflare 为 Cache API，自托管不装配）。
- **`@<scope>/storage`**：新增 `createShareCardInvalidator`、`createShareCardImageStore` 与 `Storage.shareCards`（Cloudflare 为 `FILES`，Node 为 S3 兼容存储），并新增对 `@<scope>/platform` 的依赖。jobs 的每日空间清理装配分享卡片清理。
- **`assets.run_worker_first`**：增加 `"!/fonts/share-card/*"`，分享卡片字体由静态资源直接返回；构建产物 `_headers` 为 `/fonts/share-card/*` 增加 `Cache-Control: public, max-age=31536000, immutable`、`X-Robots-Tag: noindex` 与 `nosniff`。项目改过 `run_worker_first` 或 `apps/web/scripts/og-images.ts` 的 `_headers` 时手动合并。Node 自托管在 HTTP 外层为同一路径补相同的缓存头。
- **首页包检查**：`apps/web/scripts/check-home-bundle.mjs` 除客户端首页闭包外，新增服务端首页闭包（Worker 入口加首页路由分包，取自 `dist/server/.vite/manifest.json`）检查：不得出现 `cf-workers-og`、`satori`、`resvg`、`initWasm`、`NotoSansSC-Regular` 与静态导入的 `.wasm` / `.bin` / 字体文件；缺少服务端产物时失败。项目在首页静态导入分享卡片模块会导致 `pnpm build` 失败，应改为路由内动态 `import()`。
- **构建期分享图**：`apps/web/src/features/seo/og-card.ts` 已删除；`apps/web/scripts/og-images.ts` 改用 `features/share-cards/layout.tsx` 的 `defaultShareCardLayout` 与 `src/node/share-card-renderer.ts`；字体从 `apps/web/scripts/seo/` 移到 `apps/web/public/fonts/share-card/`，并新增 Inter Latin 400/600（`.woff.bin`，许可证 `INTER-LICENSE`）。`apps/web/tsconfig.node.json` 增加 `"jsx": "react-jsx"`，`vite.node.config.ts` 的 `traceDeps` 增加 `cf-workers-og`。
- **文案**：新增 `apps/web/messages/<locale>/share-page.json` 与 `ui-preview-share-cards.json`（只提供 en、zh）。项目另有语言时补齐翻译，缺失时运行时回退到默认语言。
- **e2e**：新增 `apps/web/e2e/share-cards.spec.ts`（随夜间全量测试运行），`ui-preview.spec.ts` 增加分享卡片预览断言，`staging-acceptance/harden-deletion.spec.ts` 随删号清理调整。项目沿用模板用例时同步。
- **示例类型 `sample`**：只在测试、开发与开启 `UI_PREVIEW=true` 的环境登记，生产从不登记；项目注册同名类型时不覆盖。

## 部署顺序

1. 完成「必须执行的动作」1、2（声明 `RL_SHARE_CARD`、确认付费版），再部署 web；缺少限流绑定时分享路由在限流处失败。

## 回滚

只回退代码，不涉及数据库。回滚后 `/share-card/*` 与 `/s/*` 变为 404；`FILES` 桶中 `share-cards/` 前缀的对象与 KV 中的 `share-revoked:*` 可以保留（再次升级时继续生效）或手动删除。项目已经分享出去的链接在回滚期间不可访问。

## 已知问题

- Cloudflare 原生限流绑定在线上目前不生效（与 `RL_AUTH` / `RL_AI` / `RL_API` 相同），`RL_SHARE_CARD` 修复后自动生效；在此之前由令牌格式校验与单实例渲染并发上限 2（超出返回 503）兜底。
- 撤销对已被社交平台抓取的卡片无效：平台自行缓存预览图；浏览器与中间缓存已有的副本最长 1 天。
- 渲染没有单独的超时，由平台 CPU 时间限制兜底。
- CJK 字体是 Noto Sans SC 简体子集：谚文（韩文）、泰文等文字及扩展西里尔字母显示为方框，emoji 会被去除。
- staging 实测（add-og-images 8.2）：冷实例首次 CJK 渲染 CPU 335 ms，热实例未命中渲染 89–95 ms，缓存命中 3–7 ms；未出现超出内存或 CPU 的记录（`wrangler tail` 不提供内存数值）。冷实例含 CJK 的渲染 CPU 若在项目中超过 1500 ms，后续版本改用常用字子集。
- 衍生项目在 `brand.css` 中把页面颜色指向站点自有 token、却没有同时映射 `--surface-1`…`--surface-8` 表面阶梯时，弹层（如 0.3.x 的通知铃铛）会回落为模板的中性灰；把表面阶梯也映射到站点 token 即可（xuanxue 采纳 0.3.1 时遇到）。
