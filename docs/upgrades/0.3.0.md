## 概要

本版本是 UI 基线换代，同时带来三项业务能力，均默认关闭或保持原有行为：

- **UI 设计系统（add-ui-design-system）**：
  - 以 Fluid 为中性基线重写 `@<scope>/ui` 的 token、Button/Dialog/Select/Input，新增 AlertDialog、Textarea、Checkbox、Switch、Badge、Tooltip、Tabs、Dropdown、Sidebar、Toast、Combobox、Command Menu；
  - `template.config.ts` 新增 `ui` 段（preset / shape / density）与四套主题预设，项目品牌层固定为 `apps/web/src/styles/brand.css`；
  - 新增项目自有扩展点：`packages/ui/src/project/`、根文档属性 `html-attributes.ts`、`scripts/check-ui.allow.local.json`、`docs/design/`；
  - 新增 `pnpm check:ui`（并入 `pnpm check`）与组件指纹清单，`check:deps` 增加 UI 依赖边界；
  - 组件预览页 `/dev/ui`（仅 `UI_PREVIEW=true` 时开放）；新增 `ui-design` 技能，template-sync 技能增加截图对比步骤。
- **对话绑定对象（add-subject-chat）**：对话可绑定业务对象或临时上下文令牌，首条 system 消息作为固定前缀；推荐追问（默认关闭）、回复评分与反馈、后台 `/admin/feedback`。
- **每日登录赠送积分（add-daily-credits）**：`credits.dailyEnabled` 默认关闭，参数在后台运行时设置中调整。
- **订阅与积分包并存（add-billing-coexistence）**：共存目录、账单分类摘要、统一的余额不足错误合同（HTTP 402 + `details`）与项目功能键 `plan.features.capabilities`。

衍生项目同步后视觉会整体变化（字体、背景、圆角、按钮与输入框样式）；只要沿用模板页面，不改品牌也能直接使用。改过品牌色、根布局或原生控件的项目，按下文「必须执行的动作」逐项处理。

## 必须执行的动作

1. 把项目原有的品牌变量（自建的主题 CSS、改过的 `globals.css` 变量）迁入 `apps/web/src/styles/brand.css`，并让 `apps/web/src/styles/app.css` 恢复模板原样（`@import "@<scope>/ui/globals.css"` 之后以 `@import "./brand.css"` 作为最后一个导入）。基线与预设位于 `@layer base`，brand.css 不分层，普通 `:root` / `.dark` 选择器即可覆盖；覆盖浅色值时须同时给出 `.dark` 值。改了 `--primary` 时同时设置 `--primary-text`（文字对页面与卡片 ≥ 4.5:1），需要沿用原焦点环与输入框边框时设置 `--focus-ring`、`--field-border`。注意基线新增的 `--accent`（较重的灰色强调底）与 `--surface-1`…`--surface-8` 表面阶梯，项目自有变量与之同名时会互相覆盖，改名或确认取值。
2. 项目改过模板根布局 `apps/web/src/routes/__root.tsx`（例如在 `<html>` 上输出 `data-site`）时：把属性计算移到项目自有的 `apps/web/src/features/theme/html-attributes.ts` 的 `getProjectHtmlAttributes`，根布局改用模板的 `RootDocument`（`features/theme/root-document.tsx`，含 `UiRoot` 与 `data-preset`）。项目自有的 Context 包装放进 `RootComponent` 的子节点中，不改 `RootDocument`。函数可读取请求 `host`、`locale` 与不含语言前缀的 `pathname`，只能返回 `data-*`、`title`、`dir`、`translate`。
3. 所有 `<DataTable>` 必须传 `labels`（组件不再带英文默认文案）：app 区与公开页用 `apps/web/src/features/i18n/table-labels.ts` 的 `dataTableLabels()`（文案为 `messages/<locale>/common.json` 的 `common_table_*`），后台列表沿用 `adminTableLabels()`；项目已有等价函数时可继续使用。`DialogContent` 显示关闭按钮时必须传 `closeLabel`，`SelectTrigger` 必须传 `placeholder`；不显示关闭按钮时传字面量 `showCloseButton={false}`。
4. `pnpm check` 新增 `check:ui`：禁止颜色字面量、任意值 className（如 `text-[15px]`、`max-w-[1120px]`）、原生 `<select>` 与 `window.confirm` / `alert`，并校验 `packages/ui/components.lock.json` 指纹（存在 `.template-base.json` 时修改模板组件会失败）。项目自有代码的存量写法二选一：改用 token 工具类与 `@<scope>/ui` 组件；或逐文件登记到 `scripts/check-ui.allow.local.json`，长期例外（如第三方品牌图标、插画配色）放 `exceptions` 并写明原因，待替换项放 `pendingReplacement` 并写 `value` 与 `count`。不要修改模板的 `scripts/check-ui.allow.json`。需要定制模板组件时复制到 `packages/ui/src/project/`，在 `docs/design/forks.md` 登记来源，必要例外同样登记到 allow.local。
5. `apps/web/src/features/admin/ui.tsx` 不再导出私有的 `Textarea`、`NativeSelect`、`CheckboxField`：项目自建的后台页面改用 `@<scope>/ui` 的 `Textarea`、`Select`、`Checkbox`（替换模式见 `docs/design-system.md`）。原生 `<select>` 改用 `@<scope>/ui` 的 `Select`（服务端渲染只输出触发器，选项在展开后渲染，断言 SSR 中选项文字的单元测试要改为断言触发器或 `valueLabel`）；`window.confirm` 改用 `AlertDialog`。e2e 中 `getByLabel(…).selectOption(…)` 改用 `apps/web/e2e/select.ts` 的 `chooseOption(trigger, 选项文字 | { value })`，触发器按 `getByRole('combobox', { name })` 或 id 定位。
6. `check:deps` 新增 UI 依赖边界：`radix-ui`、`@base-ui/*`、`motion`、`framer-motion`、`lucide-react`、`class-variance-authority` 只允许 `@<scope>/ui` 依赖，`@radix-ui/*` 全面禁止。apps 中的图标改从 `@<scope>/ui/icons` 按名称导入。
7. 服务端错误合同变化：`apps/web/src/features/ai/chat.ts` 的 `chatAppError` 已删除，余额不足的 `CreditsError` 自身即带 AppError 合同，调用处直接 `toErrorResponse(error)`；`status >= 500` 或 `expose: false` 的 AppError 统一输出 `INTERNAL_ERROR`，`details` 不再写入响应，需要公开的字段改用 `publicDetails`。前端解析余额不足请改用 `@<scope>/shared` 的 `parseInsufficientCredits`，不要解析 message。
8. `apps/web/wrangler.jsonc` 顶层（开发）与 `env.staging.vars` 设置 `"UI_PREVIEW": "true"`，`env.production` 不设；`scripts/production/check-wrangler-envs.mjs` 的生产禁用变量清单加入 `UI_PREVIEW`（项目改过该脚本时手动合并）。（适用：target=cloudflare）
9. 模板新增的文案文件（`admin-daily-credits`、`ai-subject-chat`、`billing-coexist`、`billing-credit-errors`、`daily-credits`、`ui-preview`、`workspace`，以及 `common.json` 中的 `common_cancel`、`common_table_*`）只提供 en 与 zh。项目语言集不同时，删除同步带入但不使用的语言目录，并为自有语言补译；缺失的文案在运行时回退到默认语言，`pnpm test` 会列出缺失项但不失败。（适用：i18n=true）
10. 删减过模板文件或改过模板表结构的项目，同步后核对模板新增的测试：删除了 `scripts/create-project.mjs` 时，`scripts/check-ui.test.mjs` 会因导入失败让 `pnpm check` 失败，把根 `package.json` 的 `check:ui` 改为只运行 `node scripts/check-ui.mjs`；移除了 Node 目标时，删掉同步带入测试中的 `target === 'node'` 分支；移除过 `apps/web` 的 `esbuild` devDependency 时需加回（`daily-notice.test.tsx` 使用）；给 `user`、`organization` 等模板表增加过必填列时，补齐新增集成测试夹具（`packages/credits/test/daily.test.ts`、`apps/web/test/daily-workspace.test.ts`、`apps/web/test/ai-subject-chat.test.ts`）中的插入列。

## 配置变更

- `template.config.ts`（均可省略，省略取默认值；未知取值构建期报错）：
  - `ui: { preset, shape, density }`：preset 为 `neutral` | `blue` | `violet` | `green`（只换强调色与焦点环），shape 为 `sharp` | `rounded` | `pill`（目前只影响按钮、选择器与弹窗），density 为 `default`（36px 控件）| `compact`（28px）。生成器新增 `--theme`。
  - `credits.dailyEnabled`：默认 `false`；开启时同时需要 `credits.enabled=true`。
  - `ai.text.followUps: { enabled, charge, count, modelKey }`：默认 `{ enabled: false, charge: false, count: 3, modelKey: null }`；`charge=true` 时只对按 token 计价的模型生成并预扣结算。
  - 订阅套餐可在 `plan.features.capabilities` 声明中性功能键（例如 `{ "exports.advanced": true }`），缺失即拒绝；服务端用 `can(ctx, key)` / `requireEntitlement(ctx, { capability })` 检查，见 `docs/entitlement-features.md`。
- 新增运行时设置（后台可改，均有默认值）：`credits.dailyAmount`（10）、`credits.dailyMaxDaysPerMonth`（10）、`credits.dailyExpiryDays`（7）、`credits.dailyRequireVerifiedEmail`（true）；一次性邮箱黑名单沿用 `billing.signupBonusDomainBlacklist`。所有日期按 UTC。
- `dbSettingStore` 改用原始 SQL 读取 JSONB，不再对 JSON 字符串二次解析：手工写入的 `"true"`、`"10"` 等字符串保持字符串，升级前检查并纠正错误类型的设置值。
- 新增非密钥变量 `UI_PREVIEW`（见动作 8）；`packages/config` 的环境校验新增该键。没有新增 secret、部署绑定或支付 webhook 事件。
- 根 `package.json`：`check` 前置 `pnpm check:ui` 并运行 `scripts/agent-skills.test.mjs`；新增 `check:ui`、`ui:lock`。CI 的测试 job 安装 Playwright Chromium（每日领取提示的浏览器用例），本地首次运行 web 测试前执行 `pnpm --filter @<scope>/web exec playwright install chromium`。
- UI 视觉与组件行为变化（同步后全站可见）：
  - 自托管 Inter 可变字体；页面背景 `#fafafa`（深色 `#171717`），卡片与弹层为白色表面阶梯；`--radius` 0.625rem → 0.5rem。
  - 焦点环为 2px 描边加 2px 间隙（浅 `#3b82f6`、深 `#4f86f7`），shadcn 的 `--ring` 指向同一颜色。
  - 按钮：`default` 实心、`outline` 无底色、`ghost` 灰字、`secondary` 半透明灰底、`destructive` 改为浅红底红字；`link` 变体使用 `--primary-text`。
  - Input / Textarea / Select 触发器共用 `--field-border`，错误态为实色 `--destructive`；Input 的 `size` 改为 `'default' | 'compact'`。
  - `CardTitle` 由 20px 改为 16px（`text-title`），Card 说明、Alert、Label、DetailList 改用 `text-body`；需要大标题时传 `className="text-display"` 等阶梯类。
  - 悬停与当前项改用 `bg-hover` / `bg-active`；DataTable 表头 `bg-hover`、容器 `rounded-xl`，筛选下拉改为 Select（随表单提交的隐藏原生 select 仍在）。
  - Dialog / AlertDialog 退场动画期间面板为 `inert`；Sidebar 快捷键默认关闭（`shortcut` 默认 `null`）；`Toaster` 含动效库，按 `docs/design-system.md` §4 在 app / admin 布局用 `React.lazy` 挂载。
- 新增变量与工具类：`--primary-text`、`--control-border`、`--switch-thumb-on` / `--switch-thumb-off`、`--badge-*`、`--z-toast`，`scroll-divider`、`scrollbar-hide`。项目改过强调色或开关颜色时，自行确认开关滑块与轨道 ≥ 3:1（`@<scope>/ui` 的对比度用例只覆盖模板预设）。
- 业务接入点（可选）：
  - 对话绑定对象：在项目自有的 `apps/web/src/features/ai/subject-providers.ts` 注册类型（`registerConversationSubject`），页面嵌入 `<SubjectChat slug subjectType subjectId />`；临时上下文用 `issueSubjectContext` 签发，打开 `/app/<slug>/chat/context?token=…`。
  - 账单摘要：`getCustomerBilling` 返回 `summary.currentSubscription`、`nextRenewalAt` 与 `summary.credits`（`{ available, subscription: { total, currentPeriod }, purchase, free: { signup, daily, total }, other }`），见 `docs/billing-summary.md` 与 `docs/billing-credit-errors.md`；定价分组用 `groupPricingPlans` / `pricingForInterval` / `pricingFeatures`。
  - App 布局的每日领取提示 `DailyCreditsNotice`（`features/credits/daily-notice.tsx`），项目自建布局时放在空间摘要附近。

### 营销首页新区块（同步后可见）

`template.config.ts` 的 `marketing` 段新增 `stats`、`steps`、`products`、`aiEntry`。首页（`apps/web/src/routes/index.tsx`）在 Hero 之后依次渲染数据背书、
「如何开始」流程与编号产品矩阵，`MarketingShell` 在营销页右下角挂载悬浮 AI 入口。`@<scope>/config` 的默认值都是空或关闭，但模板自己的
`template.config.ts` 带了示例内容，三方合并时会带进衍生项目：

- `steps`：三步示例（注册并创建空间 / 选择工具或上传文档 / 导出结果或接入 API），区块标题「三步上线第一个 AI 功能」在
  `apps/web/messages/<locale>/marketing-blocks.json`。改成项目自己的步骤与标题，或设为 `steps: []`（区块不渲染）。
- `products`：三个示例产品（文档助手、图片生成、长文报告，主按钮指向 `/register`，次级链接指向 `#features`）。替换为项目产品，
  或设为 `products: []`（区块不渲染）。标题「一个账号，全部工具」不含数量，可在同一文案文件中修改。
- `aiEntry`：模板默认开启并指向 `/app`（与确认的设计稿一致）；文本 AI 或营销关闭时自动隐藏。不需要时设 `aiEntry: { enabled: false }`。
  开启时页脚底部会多留空白，入口叠在浮动主题切换上方。
- `stats`：模板不提供数值，默认不渲染；只填写真实可查的数值与来源。
- 文案按 `i18n.locales` 逐语言填写，缺语言在类型检查时报错，空值在构建期报错。项目语言集不同（如只有 `en`）时，按自己的语言改写或直接写字符串。
- 首页底部 CTA 改为卡片表面加主按钮（修复深色模式下按钮不可见），各营销区块 h2 统一为 `font-bold`。改过 `sections/cta.tsx` 或
  `sections/section.tsx` 的项目合并时保留自己的版本即可。

### 迁移示例：xuanxue（两站、自建对话上下文）

以下步骤已在 xuanxue 的本地同步分支上执行并通过 `pnpm check`、`pnpm typecheck`、`pnpm check:deps` 与全部单元/集成测试：

1. **`site-theme.css` 并入 `brand.css`**：把两站 token、字体 fallback `@font-face` 与 `@theme inline` 映射整体移入 `brand.css`，删除 `site-theme.css` 并更新引用它的注释与文档；`app.css` 恢复模板原样。另在 `:root[data-site]` 中把 `--focus-ring`、`--primary-text`、`--fluid-accent`、`--field-border`、`--hover` 指向站点 token，保持同步前的焦点环、链接色与输入框边框。xuanxue 的 `--accent`（品牌朱砂/金色）与 `--surface-2` 与基线同名，已在 `@theme` 中把 `--color-accent` 改回 `surface-2`，需在截图对比中确认灰色 Badge 与表面阶梯的效果。
2. **`data-site` 移到 `html-attributes.ts`**：`getProjectHtmlAttributes` 用 `resolveSite(context.host, templateConfig)` 返回 `{ 'data-site': id }`，与根 loader 的 `getCurrentSite` 同一识别规则；`__root.tsx` 改用模板 `RootDocument`，`SiteContext` 包在 `RootComponent` 的子节点外层，`SITE_THEME_SCRIPT` 仍读取 SSR 写入的 `data-site`。按 Host 分站的页面预渲染时 `host` 为构建请求的地址，与同步前相同。
3. **UI 规范例外**：OAuth 按钮的 Google 品牌色登记到 `exceptions`；工具页、命盘、塔罗、报告页等存量任意值字号与版心宽度（约 170 处）、一处原生 `<select>`（`features/tools/form.tsx`）与一处 `window.confirm`（`features/readings/report-page.tsx`）登记到 `pendingReplacement`，后续按视觉规范补充 token 工具类后逐步清零。
4. **自建 chat-context 与模板 subject 注册表**：同步时三方合并 `chat.ts`，采用模板「首条 system 消息作为固定前缀」并删除自建的 system 行读取（已有对话的 system 消息仍按首条读取，无需数据迁移），保留 `context.prompt` 携带的 `providerOptions`。自建的 `chat-context*.ts` 与 `?context=` 链接暂时保留、行为不变；迁到模板机制按下表逐步进行：

   | 自建 | 模板 |
   | --- | --- |
   | `issueChatContext(deps, { userId, context, returnTo })` | `issueSubjectContext({ secret, cache }, { userId, workspaceId, subjectType: kind, context: { version, data: result }, returnTo, suggestions?, title? })` |
   | `openChatContext` | `openSubjectContext`（同样返回 ok / expired(returnTo) / invalid） |
   | `/app/<slug>/chat?context=<token>` | `/app/<slug>/chat/context?token=<token>` |
   | `contextSystemText(context)` | provider 的 `context().text`（模板会加固定头 `[context type=… version=…]`） |
   | `data-chat-context` 数据片段 | `data-subject-context`（只存类型与版本） |
   | `createConversation({ context })` | `startTemporarySubjectConversation({ slug, token })` 或 `startSubjectConversation({ slug, subject })` |

   步骤：在 `subject-providers.ts` 用 `registerConversationSubject('reading', { label })` 注册结果类型，报告类持久对象另实现 `resolve`（校验 `workspaceId` 与 `userId`）并在报告页嵌入 `<SubjectChat subjectType="reading" subjectId={report.id} />`；`createChatContextLink` 改用 `issueSubjectContext` 与新地址，保留复算与 `safeReturnPath`；最后删除 `chat-context.ts`、`chat-context.functions.ts`、`chat-context-start.tsx` 与 `createConversation` 的 `context` 参数。旧链接 30 分钟后自然失效；已有对话没有 `subject_type`，列表不显示来源标签，需要时可按 system 消息中的 `data-chat-context` 片段回填（可选）。
5. **其他冲突处理**：项目自建的页面（定价页、App 布局、语言菜单、账单与工作区设置）保留项目结构，只吸收模板的 Select / AlertDialog 替换与新增接入（`DailyCreditsNotice`、`InsufficientCreditsGuide`、消息评分与推荐追问）；英文文案仍走项目的 `m.*()`。项目删除的 zh 语言目录随同步带回的新文件一并删除。

## 数据库变更

### 0021_daily_credits

- 类别：扩展
- 兼容上一版本代码：是
- 锁表与耗时：新建空表 `credit_daily_claim`；`metrics_daily` 新增两个带常量默认值的 NOT NULL 列（PG 11+ 只改元数据，短暂 ACCESS EXCLUSIVE）；新表到 `credit_grant` 的外键会短暂锁住 `credit_grant`（SHARE ROW EXCLUSIVE，新表为空，校验瞬时完成）。迁移设置 `lock_timeout=5s`、`statement_timeout=30s`，拿不到锁时失败，可重试
- 回滚：只回退代码，保留新表、新列与已发放的账本

`credit_daily_claim` 保存领取用户、规范化邮箱 SHA-256、UTC 日期与对应批次，用户/日期与邮箱散列/日期分别唯一；`credit_grant.source` 的 TypeScript 联合新增 `daily`（列仍为 text）。`metrics_daily` 新增 `daily_grant_count`、`daily_grant_credits`，历史行为 0。

### 0022_subject_chat

- 类别：扩展
- 兼容上一版本代码：是
- 锁表与耗时：新建空表 `ai_message_feedback` 及其到 `organization`、`ai_message`、`user` 的外键（短暂 SHARE ROW EXCLUSIVE）；`ai_conversation` 新增两个可空列（元数据变更），非并发创建索引 `ai_conversation_workspace_subject_idx`（建索引期间阻塞该表写入，耗时随行数增长），并添加未带 NOT VALID 的 CHECK 约束（持 ACCESS EXCLUSIVE 全表扫描一次）。`statement_timeout=30s`：`ai_conversation` 很大时可能超时失败，需在低峰重试，或先手工 `CREATE INDEX CONCURRENTLY` 同名索引再迁移
- 回滚：只回退代码，保留新列、索引、约束与新表

对话新增 `subject_type`、`subject_id`（同时为空或同时有值）；`ai_message_feedback` 保存回复评分与文字反馈，jobs 的 AI 内容清理会一并删除它。衍生项目经 template-sync 移植后文件名带 `tpl_` 前缀，接在项目自有迁移之后。

## 部署顺序

- **Cloudflare**：
  1. 在同步分支完成上面的动作并通过检查；
  2. 合并后由 CI 发布 staging，顺序为构建 → 迁移 → jobs → web（jobs 的指标汇总写入 `metrics_daily` 新列、AI 内容清理删除 `ai_message_feedback`，都依赖迁移先完成）；
  3. 在 staging 按「验证」检查，确认 `/dev/ui` 可访问；
  4. 推送项目自己的 `v*` tag 发布 production，确认 production 的 `/dev/ui` 返回 404。
- **selfhost**：用新 SHA 构建 image-set 与 release bundle 后正式部署（先停应用、再迁移、后启动）；`UI_PREVIEW` 默认不传即关闭预览页。
- 余额不足合同与账单摘要需后端先于前端页面生效；同一次发布中两者一起上线即可。

## 验证

- `/api/health` 返回本次完整 SHA，`db.status` 为 `up`。
- 浅色与深色下检查首页、定价页、登录页、App 主页与后台列表页：正文对比度 ≥ 4.5:1，焦点环与背景、与主按钮 ≥ 3:1；改过品牌色的项目按 template-sync 技能第 5 节在 390 与 1440 宽截图对比，`docs/design/forks.md` 登记的副本对照上游改动手动合并。
- 多站点项目：SSR 原文含 `data-site`；关闭 JavaScript 检查首屏配色；启用 JavaScript 后水合无属性变化与 mismatch。
- staging 的 `/dev/ui` 可访问、noindex 且不在 sitemap；production 返回 404。
- 每日积分（开启时）：真实账号访问 App 领取一次，第二次访问显示已领取；未验证邮箱按设置拒绝；后台指标展示领取次数与积分。
- 对话绑定对象（注册类型后）：嵌入对话回答引用对象上下文，另一账号打开同一对象返回 404；点赞、改为点踩并填写反馈、撤销后，`/admin/feedback` 统计随之变化；临时上下文令牌被修改显示无效，超过 30 分钟提示返回原页。
- 余额不足：聊天返回 HTTP 402，页面显示预计消耗与当前余额，并给出积分包与订阅入口；同空间先订阅后购买积分包，各生成一份来源批次且余额可对账（适用 billing=stripe 时用测试模式验证）。

## 回滚

两次迁移都带 `-- rollback-safe:` 注释，可回退到 0.2.2 的代码，schema 保持不变：

- Cloudflare：`gh workflow run deploy-production.yml --ref main -f tag=<旧 tag>`；
- selfhost：用旧 SHA 的 release bundle 部署。

回退前关闭 `credits.dailyEnabled` 与 `ai.text.followUps.enabled`；已发放的每日积分、领取记录、评分与对话绑定数据保留，旧代码不读写它们。项目功能键为附加 JSON 字段，随服务端授权代码一起回滚。

## 已知问题

- 长对话摘要尚未实现：历史超过输入上限时仍按原规则截断，上下文前缀保留。
- 每日领取按「邮箱散列 + UTC 日期」全库唯一。同一邮箱在项目中存在多个独立账号（例如按站点拆分账户体系）时，这些账号共享每日与每月额度；开启前按项目账户模型评估。
- `scripts/check-ui.test.mjs` 静态导入 `scripts/create-project.mjs`，删除了生成器的衍生项目需按动作 10 调整 `check:ui`；模板后续版本改为按需加载。
- UI 组件指纹以仓库中的 `packages/ui/components.lock.json` 为基准，同时修改组件与清单可以绕过比对，删除 `.template-base.json` 也会让检查按模板态运行；指纹范围目前只含 `packages/ui/src/components/`。
- Textarea 只在支持 `field-sizing` 的浏览器随内容长高，Safari / Firefox 可纵向拉伸。
- 工作台侧边栏（`ui.appLayout`）、长文阅读器、营销新区块与 R1–R4 业务展示组件尚未包含在本版本中，现有 App 布局保持不变。
- 真实 Stripe 测试模式的订阅 + 积分包并存购买验收尚未完成。
- 0.2.0 的 Cloudflare Rate Limiting 已知问题仍然存在。
