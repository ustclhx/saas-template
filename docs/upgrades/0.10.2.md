## 概要

两个来自衍生项目同步 0.10.1 的修复：

- **解决过冲突的同步分支可以续同步**：`template-sync --branch` 在同一分支同步到更晚目标时，此前要求分支上只有工具生成的提交，
  而有冲突的同步必然产生解决冲突的提交，因此续同步只对无冲突的同步有效。现在工具在本地 Git 配置
  `branch.<分支>.template-sync-start` 中记录每轮同步的起点，轮内（应用模板变更之后、基准提交之前）的解决冲突与修复提交
  不再阻止续同步；第一轮起点之前或最后一个基准提交之后的其他提交、合并提交仍然拒绝。已有分支没有轮次记录，
  沿用原来的严格核对：用本版本工具新建的同步分支才能享受新规则（工具以项目中的脚本运行，采纳本版本后的下一次同步生效）。
- **`verification` 附加列的类型**：`@saas/auth` 的重新验证服务把模板列与 `stepUpVerificationColumns` 返回的附加列合并后，
  在一处断言为该表的完整插入类型。项目给 `verification` 加了必填列（如多站点的 `site`）时不再需要在模板文件中加类型断言；
  在 0.10.1 中自行加了断言的项目，同步时以模板为准即可。

## 验证

- `pnpm typecheck` 通过，`packages/auth/src/admin-step-up.ts` 与模板一致（不再含项目自加的断言）。
- 下一次有冲突的模板同步：解决冲突并完成同步后，在同一分支用 `--branch <分支> --to <更晚版本>` 续同步不再报「含有不属于模板同步的提交」。

## 回滚

只回退代码即可，无数据库与配置变更。本地 Git 配置中的轮次记录可以保留，旧版工具会忽略。
