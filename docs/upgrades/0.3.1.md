## 概要

- **反馈共享对话同意（add-subject-chat 10）**：用户点踩提交反馈时可勾选「共享这段对话」（默认不勾选，每条反馈单独同意，可撤回）；只有同意的反馈，后台 `/admin/feedback` 才能查看被评回复与它之前最近 3 条消息，每次查看写审计。

## 必须执行的动作

无

## 配置变更

- 文案文件 `apps/web/messages/<locale>/ai-subject-chat.json` 新增 `subject_chat_feedback_share`、`subject_chat_feedback_share_description` 与若干 `admin_feedback_*` 键，并修改 `admin_feedback_description`；项目新增语言时补齐翻译。
- 隐私说明：启用 AI 对话的项目上线前应在隐私政策中说明这项共享——用户可以在反馈时选择把被评回复和它之前最多 3 条消息共享给平台管理员用于改进回答，不包括关联对象的上下文；同意逐条记录、可随时撤回；说明这些内容的保留期限（随对话删除、删号与删空间清理一并删除）。模板不修改法律页正文。

## 数据库变更

### 0024_feedback_share

- 类别：扩展
- 兼容上一版本代码：是
- 锁表与耗时：`ai_message_feedback` 新增 `share_conversation boolean not null default false`（常量默认值，PostgreSQL 11+ 为元数据变更，不改写表）、可空列 `shared_at timestamptz`，以及 check 约束 `ai_message_feedback_shared_at_consistent`（`share_conversation = (shared_at is not null)`，未带 NOT VALID，持 ACCESS EXCLUSIVE 扫描一次全表；已有行恒为 false 与 NULL、表通常很小，校验瞬时完成）。迁移设置 `lock_timeout=5s`、`statement_timeout=30s`，拿不到锁时失败，可重试
- 回滚：只回退代码，保留新列与约束；旧代码不读写这两列（插入时取默认值 false 与 NULL，满足约束），新代码写入的同意保留

数据迁移：无，已有反馈一律视为未同意，后台不显示其对话正文。

接口变化：`apps/web` 的 `MessageFeedbackValue` 新增必填字段 `shareConversation: boolean`，自行构造该值的项目补 `shareConversation: false`；`@saas/ui` 的 `MessageFeedback` 新增可选属性 `shareLabels: { label; description }`（不传时不显示勾选项，行为与此前一致），`MessageFeedbackValue` 新增可选字段 `shareConversation`。后台可见范围由 `apps/web/src/features/ai/feedback.ts` 的 `FEEDBACK_SHARED_PRIOR_MESSAGES`（3）控制，修改时同步隐私政策与勾选项说明文案。

## 部署顺序

先执行迁移，再部署 web（新代码读写 `share_conversation` 与 `shared_at`）；jobs 不涉及。

## 验证

1. 在对话页对一条回复点踩，展开的表单中「共享这段对话」默认未勾选；勾选后提交，刷新页面并点「修改反馈」，勾选仍在。
2. 平台管理员打开 `/admin/feedback`：该条显示「已共享」与「查看对话」，打开后看到被评回复与之前的提问，审计日志新增 `ai.feedback.view_conversation`（只含反馈 ID、空间、消息 ID 与条数）。
3. 回到对话页取消勾选并重新提交：后台该条显示「未共享」，再请求对话正文返回不存在。

## 回滚

回退代码；保留新增列与约束即可，不需要回退数据库结构。
