## 概要

新增站内链接规范（OpenSpec `seo-internal-linking`）：页面声明层级与主词，公开页自动带面包屑与内链区块，构建后检查实际渲染出的链接图。规则、字段与配置见 [站内链接规范](../seo-internal-linking.md)。

- **页面层级与主词**（#433）：`SeoPage` 新增 `parent`、`titleMain`、`anchorShort`、`group`、`related`、`indexable`、`priority`、`sourceLocale`。
  - 博客、文档、答案页、法律页按集合自动推导上级，frontmatter 可用 `parent`、`anchor_short`、`related` 覆盖。
  - 项目自有的公开页面在新文件 `apps/web/src/features/seo/pages.project.ts` 中注册。该文件首次同步后归项目所有，文件内的示例注释可按项目改写，注册方法与中性示例见规范 §5。
  - 构建时校验：同语言地址唯一；可索引页必须有主词，除首页外必须有上级；`parent`、`group`、`related` 的目标存在且可索引。失败时构建中止，并给出页面地址。
- **多语言回退**（#433）：缺少译文、以原语言内容显示的页面，canonical 改为指向原语言页；hreflang 只列真实译文；这些页面不再进入站点地图与 `llms.txt`。
- **内链区块**（#432、#434）：`@saas/ui` 新增 `Breadcrumb`、`Pagination`、`LinkCard`、`LinkCardGrid`、`SeriesNav`、`LinkList`。
  - 博客、文档、答案页、法律页、定价等公开页显示面包屑与 BreadcrumbList 结构化数据，面包屑取代原先的「← 返回」链接。
  - 正文后依次显示系列上一篇／下一篇、相关、同组区块，未声明的区块不渲染。
  - 博客列表与标签页超过 `seo.linking.hubPageSize` 时分页（`/blog/page/<n>`）。
- **构建后链接图检查**（#431、#435）：`pnpm --filter @saas/web check:links` 在构建后启动 preview 抓取站点地图中的页面，检查孤岛、死链、指向不可索引页、禁用锚文本、姊妹站链接约束（必须 `nofollow`、不进导航层、不镜像互指）等。
  - 规则分失败、警告两级。页头、页脚、面包屑标为导航区，注册与应用入口标为 `action` 区，这两类区域的链接不计入「指向不可索引页」。
  - CI 的 `build` job 在 `pnpm build` 之后运行该检查。
  - `seo.linking.mode` 未配置时为 `report`，只报告不失败；模板仓库自身配置为 `enforce`。
- **其他**：首页产品矩阵的「了解更多」改为具体文案；OG 分享图清单补上了答案页。

## 必须执行的动作

无

## 配置变更

- `template.config.ts` 可新增 `seo.linking` 段。不配置时检查只报告，阈值使用默认值。字段与默认值见 [站内链接规范 §4](../seo-internal-linking.md)。

无

无

## 验证

```sh
pnpm check
pnpm typecheck
pnpm build
pnpm --filter @saas/web check:links --mode report
```

报告中各规则的命中数为迁移起点。项目确认孤岛、死链与指向不可索引页的问题都已处理后，在 `template.config.ts` 设 `seo: { linking: { mode: 'enforce' } }`。

## 回滚

回退本版本代码即可。回退后回退页的 canonical 恢复为指向自身。

## 已知问题

- 衍生项目的页头、页脚若已改为项目文件，需要自行加上 `data-link-zone="nav"`；否则报告出现 `no-nav-zone` 警告，导航链接也会按正文计入「指向不可索引页」。
- 只读副本试跑（以 xuanxue 为例）发现的典型问题，供迁移参考：站点地图的语言前缀大小写与路由不一致造成死链；程序化详情页的 hub 未注册，或没有从可索引页链接到，导致这些页面不可达。
