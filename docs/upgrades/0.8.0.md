## 概要

按多语言 SEO 规范 ML-01～ML-10（[docs/multilingual-seo.md](../multilingual-seo.md)）调整语言路由、hreflang、
未翻译页与语言提示（#440–#445）。目标是每个语言有一个能单独收录的网址。

不兼容点：
- 未翻译页默认返回 404；
- 服务端语言建议横幅与偏好 Cookie 已移除；
- 语言前缀改为小写，`/<默认语言>/…` 301 到无前缀地址。

- **未翻译页默认不发布**（#442）：
  - 新配置 `i18n.untranslated`，默认 `'hide'`。缺少译文的博客、文档、答案页与法律页在该语言下返回 404，不进站点地图、hreflang、列表、标签页与区块。
  - `'fallback'` 保持 0.7.4 起的回退行为（canonical 指向同站原语言）。
  - `'hide'` 下页面清单中仍有回退页（`sourceLocale` 与 `locale` 不同）时构建失败。
- **本地化 slug**（#442）：`SeoPage.alternates`（语言 → 不带前缀的路径）声明各语言地址，hreflang、站点地图与语言切换器都使用它。构建时校验语言合法、目标存在且可索引、双方互相声明。
- **小写前缀与默认语言唯一地址**（#444）：
  - 语言前缀为小写语言 id（`zh-Hant` → `/zh-hant`），大小写不同的写法 301 到小写地址。
  - `/<默认语言>` 与 `/<默认语言>/…` 301 到无前缀地址（此前为 Paraglide 的 307）。
  - 两个语言 id 只差大小写时配置报错。
  - `<html dir>` 按语言输出。
- **语言提示条与切换器**（#445，设计稿见原型索引「语言提示条」）：
  - 移除 `<head>` 首帧脚本、服务端渲染的隐藏横幅与 `locale-preference` Cookie。
  - 新的 `LanguagePrompt` 在水合后挂载，只提示本页 hreflang 中的语言，关闭状态存在 localStorage。
  - 语言切换器改为普通链接的下拉菜单 `LanguageMenu`，公开页只列出本页真实存在的语言。
  - `@saas/ui` 新增 `LanguagePrompt`、`LanguageMenu`、`Languages` 图标与 `float-enter`／`float-exit` 动画。
- **首页记住语言（ML-09，可选）**（#445）：
  - 新配置 `i18n.rememberHomeLocale`，默认 `false`。
  - 开启后，已登录且手动选过语言的用户打开默认语言首页时，转到所选语言首页。
  - 退出登录统一经 `signOut()` 帮助函数，并清除浏览器中的标记。
- **多语言检查**（#443）：`check:links` 新增失败级规则：
  - 页面与 hreflang：`canonical-self`、`html-lang`、`lang-query-link`、`hreflang-reciprocal`、`hreflang-cross-host`、`hreflang-x-default`、`hreflang-target`；
  - 请求与响应：`accept-language-vary`、`language-set-cookie`、`default-locale-prefix`、`language-prompt-ssr`。
  - 新增可选配置 `seo.linking.languageCookies`，以及参数 `--accept-language-samples`。

## 必须执行的动作

1. 确认未翻译页的处理方式：默认 `'hide'` 会让已被收录的回退页地址变为 404；需要保持现状时在 `template.config.ts` 设 `i18n: { untranslated: 'fallback' }`，否则先补译文或接受这些地址退出索引。项目自有页面若在 `pages.project.ts` 中返回了回退条目（`sourceLocale` 与 `locale` 不同），在 `'hide'` 下要删除，否则构建失败。
2. 移除对旧语言建议的引用：`features/i18n/suggestion.ts`（`localeSuggestionScript`、`SUGGESTABLE_LOCALES`、`suggestionTargets`、`suggestionCss`、`PREFERENCE_COOKIE` 等）与 `data-locale-suggestion*` 属性已删除，项目代码或 e2e 中的引用会在类型检查或测试中报错。改用模板根布局挂载的 `LanguagePrompt`；保留自有提示组件时，只需满足 `language-prompt-ssr` 规则（不在服务端 HTML 中输出）。
3. 语言 id 含大写字母（如 `zh-Hant`）的项目，把站内硬编码的 `/zh-Hant/…` 地址改成小写；旧地址会 301，但站内链接应直接写新地址。
4. 自定义的退出登录入口改用 `apps/web/src/features/auth/auth-client.ts` 导出的 `signOut()`，以便清除 ML-09 的浏览器标记；没有自定义退出入口的项目无需处理。
5. 同步后先运行 `pnpm --filter @saas/web build` 与 `pnpm --filter @saas/web check:links --mode report`，按报告修正 hreflang 与 canonical。

## 配置变更

- 新增 `i18n.untranslated: 'hide' | 'fallback'`，默认 `'hide'`。
- 新增 `i18n.rememberHomeLocale: boolean`，默认 `false`。
- 新增 `seo.linking.languageCookies: string[]`，默认 `[]`：项目自有的语言 Cookie 名，供 `language-set-cookie` 识别。
- `SeoPage` 新增可选字段 `alternates`。

## 数据库变更

无

## 部署顺序

无。前缀与默认语言前缀的 301 随 Worker 部署生效，不需要额外的 CDN 规则。

## 验证

```sh
pnpm check
pnpm typecheck
pnpm test
pnpm build
pnpm --filter @saas/web check:links
curl -sI https://<域名>/ -H 'Accept-Language: zh-CN'   # 200，没有 Location
curl -sI https://<域名>/<默认语言>/pricing           # 301 → /pricing
```

部署后在浏览器语言与页面语言不同的环境中打开一个有译文的页面：水合后出现提示条，查看源代码时 HTML 中没有提示。

## 回滚

回退本版本代码并重新部署即可，不涉及数据库。回退后，未翻译页恢复为回退显示，小写前缀的 301 消失。语言 id 含大写字母的项目回滚前，先确认小写前缀地址在旧版本中仍可访问。

## 已知问题

- ML-09 依赖浏览器中的登录标记（7 天有效）：在服务端撤销会话、但设备上没有退出时，最多 7 天内首页仍可能转到所选语言。
- 模板内置内容集合（博客、文档等）不支持各语言不同的 slug；项目自有页面用 `alternates`。
