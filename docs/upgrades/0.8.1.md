## 概要

修复衍生项目采纳 0.8.0（多语言 SEO 规范）时遇到的模板侧问题。全部为新增的可选配置或兼容修复，不配置时单站点行为与 0.8.0 相同。

- **多站点默认语言**：`seo.linking.sites[]` 新增可选 `defaultLocale`，表示该站点的无前缀语言，`null` 表示全部带前缀。
  - 链接图检查的站点首页与 `default-locale-prefix` 按站点默认语言执行；x-default 的默认规则先取本页站点的默认语言。
  - 请求时的 301 规范化按站点执行需要项目接线：模板配置中没有生产域名，无法在请求时把 Host 对应到站点。
  - 模板提供纯函数 `siteRouting`、`localePath`、`pageXDefaultLocale`（`features/i18n/locale-url.ts`），以及 `request.server.ts` 中的接线点 `requestRouting()`。
  - `localeRedirect`／`canonicalLocalePath` 只处理传入站点的语言，其他站点语言的前缀原样放行。
  - 接线方法见 [多语言 SEO 规范「多站点」](../multilingual-seo.md#多站点)。
- **x-default 偏好**：新增 `seo.linking.xDefaultLocales`（有序），站点可用 `sites[].xDefaultLocales` 覆盖。
  - x-default 指向本页存在的第一个偏好语言；模板 hreflang 输出与 `hreflang-x-default` 检查使用同一规则。
  - 未配置时输出不变，检查只核对条数。
- **自有语言提示标记**：新增 `seo.linking.promptMarkers`，`language-prompt-ssr` 同时识别项目自己的属性名（如 `data-locale-prompt`）。
- **浏览器语言匹配不跨地区**：`preferredLocale` 不再把 `pt-PT` 匹配到 `pt-BR`，只回退到没写地区（`pt`）或地区相同的配置语言；`zh-TW` → `zh-Hant` 等书写系统匹配照常。
- **`paraglideOptions` 兼容**：
  - 0.7.x 的三参数写法 `paraglideOptions(prefixes, root, enabled)` 重新生成与 301 规范化一致的小写前缀规则，语言从 `project.inlang/settings.json` 读取。
  - 0.8.0 的四参数写法照常可用；也可以把语言配置放在第一个参数：`paraglideOptions(i18n, prefixes, root)`。
- **测试**（`pnpm test:create-project:verify` 三种组合均通过）：
  - `template.test.ts` 的未翻译页默认值用例改按 `templateConfigDefaults` 断言，改了默认语言的衍生项目也能通过。
  - `language-controls.test.tsx` 的触发器名称与当前语言名按项目默认语言取值；在关闭多语言的项目中，该文件也能通过类型检查。
  - `route-registration.test.ts` 放宽超时，避免新副本冷启动转译时超时。
- **UI 预览**：`LanguagePrompt` 示例改用语言自称作示例文案，不再依赖 `i18n_prompt_*` 文案。不使用语言提示条的项目可以删掉这些键。

无

## 配置变更

- 新增 `seo.linking.sites[].defaultLocale?: string | null`，必须是该站点的语言；省略时站点包含 `i18n.defaultLocale` 则为它，否则为 `null`。
- 新增 `seo.linking.sites[].xDefaultLocales?: string[]`。
- 新增 `seo.linking.xDefaultLocales: string[]`，默认 `[]`，语言必须是已配置语言且不重复。
- 新增 `seo.linking.promptMarkers: string[]`，默认 `[]`，HTML 属性名，结尾 `*` 表示前缀匹配。

## 验证

```sh
pnpm check
pnpm typecheck
pnpm test
pnpm --filter @saas/web build
pnpm --filter @saas/web check:links
pnpm test:create-project
```

多站点项目在配置 `sites[].defaultLocale` 与接线 `requestRouting()` 后，对每个站点主机执行 `curl -sI https://<站点域名>/<站点默认语言>`，应 301 到 `/`。

## 回滚

回退本版本代码即可。回滚前删除 `template.config.ts` 中新增的 `defaultLocale`、`xDefaultLocales` 与 `promptMarkers`，否则 0.8.0 的类型检查会把它们报为未知字段。

## 已知问题

- Paraglide 的 URL 规则和 `localizeHref` 只认全局默认语言。站点默认语言与 `i18n.defaultLocale` 不同时，需要项目按 Host 生成 URL 规则或自行本地化链接。
