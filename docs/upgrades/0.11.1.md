## 概要

- **登录保持 30 天并记住上次登录方式**：新增 `auth.sessionDays`（默认 30，取值 1–365）。会话有效期从 Better Auth 默认的 7 天改为
  `sessionDays` 天，同一浏览器期间内访问过就滚动续期（每天最多续一次）。登录页在服务端读取 Better Auth `lastLoginMethod`
  插件写入的 Cookie，给上次使用的入口标出「上次使用」，邮箱类方式默认展开。Cookie 只存方式名，不存邮箱。
  管理员敏感操作仍按 `admin.stepUpMinutes` 要求重新验证。见 `docs/04-auth-and-tenancy.md`「登录保持」。
- **管理员 MCP 可查积分批次**：新增只读工具 `credits.grants`（按空间列出批次的剩余与状态，可按状态筛选），
  `credits.ledger` 每条流水带 `grantId`，`credits.adjust` 收回时的 `grantId` 从这里取。此前只读工具查不到批次 ID，
  MCP 无法收回积分。
- **确认链接写明账号**：`needs_owner_confirm` 的 `message` 说明须用令牌所属管理员账号登录后打开，非管理员账号会看到 404。

## 必须执行的动作

无

## 配置变更

- `template.config.ts` 的 `auth` 新增可选 `sessionDays`（默认 30）。想保持原来的 7 天时写 `sessionDays: 7`。
  修改只影响之后创建或续期的会话。

## 验证

- 登录后关闭浏览器再打开，仍处于登录状态；退出登录后打开 `/login`，上次使用的方式旁显示「上次使用」。
- 管理员 MCP `tools/list` 含 `credits.grants`；`credits.ledger` 的行带 `grantId`。

## 回滚

只回退代码即可。已签发的 30 天会话在回退后按其原有效期继续有效；需要立即缩短时在后台撤销会话。
