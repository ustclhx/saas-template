# 配置功能模型

## 1. 核对环境、功能与模型

从任务确认目标环境、功能 ID 和预期使用的模型或沿用来源。连接该环境的 Admin MCP 并读取 `tools/list`。缺连接或权限时交付需要的端点与 scope，由管理员从钥匙串配置令牌。[管理员 MCP](../../../docs/admin-mcp.md)

调用 `features.models` 和 `settings.get`，核对功能种类、显式设置、沿用顺序及当前生效来源。尚未登记的功能先按项目规范添加登记，确认目标部署已加载该功能键。[功能模型登记](../../../docs/06-ai.md#功能模型)

用 `models.list` 核对候选模型的种类、启用状态、Provider、参数、定价与备用链 `fallbacks`。被沿用的功能须已显式选择一个可用模型。需要准备模型或核对套餐授权时，使用 `add-ai-model`。[添加 AI 模型](../add-ai-model/SKILL.md)

完成标准是确认目标功能的设置键和预期结果，包含模型键、解析来源及允许的套餐。

## 2. 预览后保存

用 `settings.set` 传入 `key: "ai.model.<feature>"`、要保存的 `value` 和 `dryRun: true`。显式选择时填写模型键，沿用时填写空字符串。已有模型需调整且任务包含该变更时，先用 `models.update` 预览所需字段，并确认变更对共用模型的功能有何影响。

功能上线需要主备时（主服务商限流或故障时自动改用备用），在功能所选模型上配置备用，而不是为功能另选模型：先用 `models.update` 传 `key`、完整的 `fallbacks`（`[{ modelKey, paramMap? }]`，至多 2 个，顺序即尝试顺序）和 `dryRun: true` 预览。备用须同类型、服务商与主模型及彼此不同；媒体字段名不同时用 `paramMap` 映射（主字段 → 备用字段）。`MODEL_FALLBACK_INVALID` 会指出不兼容的模型与字段，按提示修正。备用链挂在模型上，共用该模型的其他功能会同时获得这条备用链，预览时一并核对。传 `[]` 清除。参数规则见 `add-ai-model` §2。

核对新旧值和目标环境。任务授权配置且预览符合预期时，以 `dryRun: false` 保存。调用结果有歧义时先读回设置或模型。读回 `settings.get` 或 `features.models`，确认模型键和 `explicit` 或 `inherited` 来源符合预期。沿用时还应核对 `from`。

完成标准是设置读回与预期一致，能在后台审计或 `audit.list` 找到对应写入记录。

## 3. 验收功能

通过功能的正常入口验证实际采用的模型与套餐权限。真实模型调用已获授权时，用目标环境中有权限和足够积分的测试空间验证一次成功路径，核对结果与积分结算。配置了备用时，每一对主备都要用真实生成验收一次：按 `add-ai-model` §5 先确认备用在映射后的参数下产出规格一致，再在 staging 用故障注入让主模型失败，确认功能入口切换到备用、实际模型记录正确、扣费仍按主模型。未做真实生成验收的主备对列为待验收，不能只以保存校验通过为准。交付环境、功能和模型键、解析来源、备用链、审计定位及实际验收结果（含每对主备）。缺权限或测试条件时，具体标明尚未验证的环节。
