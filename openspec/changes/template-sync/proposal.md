# Proposal

## Why

用本模板生成的站点（如 xuanxue-saas）没有办法采纳模板之后的更新。原因有三个：
- 生成器复制时排除了 `.git`，副本与模板没有共同的提交；
- 副本没有记下自己基于模板的哪个提交，也没有记下生成时的参数；
- 生成时改了包作用域、Worker/Queue/Workflow/R2 名称和品牌，模板的 diff 无法直接套用。

xuanxue 生成于 2026-10-19，之后模板又合并了 harden 系列的计费、安全和验收修复，还新增了 6 个迁移。其中 `0013` 已和 xuanxue 自己的 `0013_superb_excalibur` 撞号。衍生站点越多、越晚处理，补齐越难，所以现在就要有一条可重复的同步路径。

模板也没有自己的版本号体系。现有的 `v0.1.x` tag 是演示站的生产发布，`v*` 会触发生产部署；衍生项目无法知道「从哪一版升到哪一版、要做什么手动动作、数据库会怎么变」。只靠 diff，看不出哪些迁移会删列、哪些需要新增密钥、哪些必须先部署上一版再继续。

## What Changes

1. **记录模板基准**：生成器在副本根目录写入 `.template-base.json`，内容包括：
   - 模板仓库地址与完整提交 SHA；
   - 规范化后的全部生成参数；
   - 已并入的模板迁移清单。

   同一份模板源与同一组参数，生成结果 MUST 逐字节一致。
2. **确定的干净源**：同步时不从工作区生成，而是从模板指定提交的干净检出生成，并使用该提交自带的生成器，避免本地未提交文件和新旧生成器差异混入。
3. **同步工具**：模板提供 `scripts/template-sync.mjs`，在衍生项目中按以下步骤执行：
   1. 读取基准记录；
   2. 按基准提交与目标提交各生成一份干净副本；
   3. 对比两份副本，得到已经改过名的变更；
   4. 用三方合并应用到衍生项目的新分支；
   5. 列出冲突与需人工处理的文件；
   6. 运行安装、typecheck 和单元测试；
   7. 成功后更新基准记录。

   同步工具始终从目标版本的模板取用，因此衍生项目里的旧副本不会使用过期逻辑。
4. **迁移移植约定**：
   - 模板迁移不随文件 diff 合并，由同步工具单独移植：按模板顺序追加到衍生项目迁移序列的末尾，重新编号并使用新的时间戳。这样已应用过项目自有迁移的数据库不会跳过它们。
   - 项目自有迁移与模板迁移在命名上可区分。
   - 基准记录登记已移植的模板迁移，避免重复移植。
5. **基准推断**：为没有基准记录的已有副本（xuanxue-saas）提供推断命令：
   1. 从副本首个提交的配置还原生成参数；
   2. 在给定时间窗内逐个候选模板提交重新生成；
   3. 与首个提交比对，取差异最小者；
   4. 写入基准记录前，展示比对结果并等待确认。
6. **template-sync 技能**：新增双目录技能 `template-sync`，随生成器进入衍生项目。它引导预检、同步、冲突处理、迁移核对与验证。合并、推送和开 PR 前，先列出动作并取得确认。

7. **模板版本与按需发版**：
   - 模板以 annotated tag `template-v<SemVer>` 发版，不使用会触发生产部署的 `v*`；
   - 版本级别按衍生项目是否需要手动处理来划分；
   - 没有固定周期，按需发布；首个版本为 `template-v0.2.0`；
   - 发布流水线只校验 tag 并创建 GitHub Release，不部署。
8. **版本升级说明**：每个版本附带 `docs/upgrades/<版本号>.md`，描述从上一版本升到本版本的变化，跨版本时按顺序串读。固定章节包括：
   - 必须执行的动作；
   - 配置与密钥名称变更；
   - 数据库变更：逐个迁移写明类别、兼容性、锁表风险与回滚方式；
   - 部署顺序、验证与回滚。

   `scripts/template-release.mjs` 从 diff 起草说明，并校验迁移清单是否完整。
9. **迁移兼容规则**：
   - 每个版本的迁移必须与上一版本的代码兼容；
   - 删除、重命名、加约束等收缩变更拆成两个版本完成，用 `requiresDeployed` 声明依赖的版本；
   - CI 要求收缩语句带 `-- template-contract:` 注释。
10. **同步按版本进行**：
    - 同步默认目标是最新的发布版本；
    - 报告汇总区间内的升级说明与待办动作；
    - 遇到 `requiresDeployed` 边界时分段同步；
    - 基准记录增加 `version` 字段。

## Capabilities

### New Capabilities
- `template-sync`：衍生项目采纳模板更新，包括基准记录的读写、两份干净副本对比合并、迁移移植、基准推断，以及同步结果的验证与报告。

- `template-release`：模板版本号与 tag、版本级别、每个版本的升级说明（含数据库变更说明）、迁移兼容规则、发版草稿与校验。

### Modified Capabilities
- `project-bootstrap`：生成器新增两项要求：写入模板基准记录；同源同参数时生成结果确定。
- `agent-skills`：技能清单加入 `template-sync`，沿用双目录一致、先预检再授权的规则。

## Impact

- **代码**：
  - `scripts/create-project.mjs`：写入基准记录、规范化参数，保证生成结果确定；
  - 新增 `scripts/template-sync.mjs`、`scripts/template-sync.test.mjs`；
  - 新增 `scripts/template-release.mjs`（draft / check / lint-migrations）及测试，只在模板中使用；
  - 新增 `.github/workflows/template-release.yml`，CI 增加迁移标注检查与升级说明校验；
  - 迁移移植逻辑依赖 `packages/db/migrations` 的 Drizzle journal 与 snapshot 格式。
- **技能**：新增 `.agents/skills/template-sync/` 与 `.claude/skills/template-sync/`。
- **文档**：
  - `docs/create-project.md` 增加「采纳模板更新」一节；
  - `docs/02-project-structure.md` 说明 `.template-base.json`、迁移约定与两套 tag 的用途；
  - 新增 `docs/upgrades/`：索引、骨架和首个版本 `0.2.0.md`。
- **发布**：推送首个 tag `template-v0.2.0`。这是对外操作，需要用户确认。
- **衍生项目**：xuanxue-saas 需要补写基准记录，并做一次同步到 `template-v0.2.0`、只到本地分支的演练，用作验收。它自有的 `0013` 迁移需按新约定处理。
- **外部依赖**：同步时需要能拉取模板仓库（公开 GitHub 仓库），不需要任何密钥。
- **不包含**：
  - 自动解决冲突；
  - 反向把衍生项目的改动贡献回模板；
  - 在衍生项目的线上环境执行迁移，迁移仍走各项目原有的部署流程。
