# Proposal

## Why

前几个 change 只为运营留了最小入口（模型编辑、回调重放、退款审核）。站点上线后，运营者需要在不改数据库的前提下处理用户问题（封禁、代登录排查、补发积分）、查看订阅与付款、调整运行时设置，并且所有这些操作都必须留下审计记录（`docs/04-auth-and-tenancy.md` §2、`docs/08-roadmap.md` Phase 5）。

## What Changes

- 后台用户管理：搜索、详情、封禁 / 解封、模拟登录（有明显提示、可随时退出、全程审计）、调整积分。
- 后台空间管理：查看空间、成员、订阅、余额与欠费；恢复软删空间。
- 后台计费：订阅、一次性购买、付款、回调事件（查看 / 重放）、退款申请审核，整合前面 change 的最小页面。
- 模型与定价管理（在 `add-ai-text-chat` 最小编辑页基础上补全）、系统设置（`setting` 表，含注册开关、公告、一次性邮箱黑名单）。
- 审计日志查询。
- 业务指标看板：注册、付费转化、MRR、积分消耗（含平台承担的超额）、任务成功率。

## Capabilities

### New Capabilities
- `admin-console`: 平台管理员可执行的用户、空间、计费、模型与设置管理操作及其约束。
- `audit-log`: 需要留痕的操作范围、记录内容与查询方式。

### Modified Capabilities
（无。各业务能力的行为不变，后台只是调用已有能力的管理入口。）

## Impact

- 依赖前面所有业务 change（auth、billing、AI 文本与媒体）。
- 不新增业务表；可能为指标看板新增物化视图或汇总表。
- `/admin` 路由与 `apps/web/src/features/admin` 大幅扩充。
