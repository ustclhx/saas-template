# Design

## Context

- 模板的 `packages/shared` 不依赖其他内部包，只包含类型、错误、ID、时间、日志等基础能力。`fx` 模块遵循同样的边界：只依赖 `errors` 与 `log`。
- Worker 与 Node 运行时都提供 `fetch` 与 `AbortSignal.timeout`；缓存由调用方提供，以便接入 KV、Cache API 或内存实现。

## Goals / Non-Goals

**Goals**
- 调用方一次调用即可获得 USD 基准的汇率表，并知道数据来自实时还是参考值。
- 服务商失败、超时或响应不合法时不影响调用方，且不把错误数据写入缓存。

**Non-Goals**
- 不做货币格式化与页面展示；展示由项目决定。
- 不接入需要密钥的付费汇率服务；需要时可由调用方传入其他 `url` 与校验。
- 不替代支付服务商的结算汇率。

## Decisions

1. **数据源**：默认 Exchange Rate API 的开放端点，无需密钥，每日更新。替代源（ECB 参考汇率）不含所有目标货币，因此不作为默认。
2. **缓存**：通过 `FxStore` 接口由调用方注入，键为 `fx:usd:v1`，TTL 默认 12 小时。缓存只保存 `source: 'live'` 的结果；回退结果不缓存，下一次调用重新尝试。
3. **合并**：服务商缺失的货币使用调用方的参考值补齐，避免页面因个别货币缺失而无法估价。
4. **校验**：结果必须为 `success`、基准为 USD，汇率为正的有限数，货币代码为三位大写字母；任一不满足即整体视为失败。
5. **署名**：以常量导出，由使用方在页面渲染。

## Risks / Trade-offs

- 免费端点无 SLA：通过超时（默认 5 秒）与回退参考值降低影响，回退时 `source` 为 `fallback`，调用方可据此标注「约」或隐藏估价。
- 每个运行实例各自缓存：实例数较多时请求量仍然有限（每实例每 12 小时至多一次）。
- 参考值会过时：调用方应保留定期人工校准的参考值。
