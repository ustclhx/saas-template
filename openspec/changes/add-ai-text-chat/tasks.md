- [ ] 2.1 在 `packages/ai/text` 按 `ai_model.provider` 构造经 AI Gateway 的 AI SDK 模型实例，验证本地对一个真实服务商发起一次调用成功（手动或带密钥的集成测试）
- [x] 2.2 实现输入 token 保守估算与按余额计算最大输出长度，验证单元测试：余额只够 1000 输出 token 时上限被压到约 1000、不足最小输出时报余额不足
- [x] 2.3 实现 `POST /api/ai/chat`：权益 → `RL_AI` 限流 → 欠费 / 余额检查 → 保存定价快照 → 预扣 → 插入 streaming 消息 → `streamText` → `waitUntil(consumeStream())` → `onFinish` 结算，验证集成测试（模拟模型）覆盖正常完成、实际少于预扣、实际多于预扣三种结算
- [x] 2.4 实现停止接口与出错处理（按 token 按已产生用量、按次有输出才扣费），验证测试覆盖停止与「无输出即出错」场景
- [x] 2.5 实现用量检查点：在 `waitUntil` 读流过程中每 5 秒或每 200 个输出 token 写入 `usage_checkpoint` 与已生成内容（写入失败只记日志），验证测试：模拟长流时检查点按间隔更新、正常完成时以最终 usage 结算不受检查点影响
- [x] 2.6 注册 `ai_message` 的超时兜底处理器，验证测试：未结算的预扣 10 分钟后，按 token 有检查点时按检查点用量结算、无检查点时收最低费用，按次无输出时释放
- [x] 2.7 验证客户端断开场景：e2e 中在流式输出过程中关闭页面——剩余输出在 30 秒内时重新打开后回复完整且按完整用量结算；用超过 30 秒的模拟长流验证部分回复可见、兜底按检查点结算
- [x] 2.8 估算结算封顶（决策 11）：停止、出错、超时兜底按估算结算时金额不超过预扣额，不触发超额容忍；正常完成按真实 usage 的路径不变，验证测试：英文长文本停止时估算高于预扣，扣费等于预扣额且无补扣、无欠费、对账不变式成立
- [ ] 2.9 实际用量优先（决策 12）：AI Gateway 请求带可回查标识，在 staging 验证被中断流的日志用量与查询延迟，确定即时查询或延后对账并实现，估算仅在取不到实际用量时使用；验证测试覆盖取到实际用量、取不到时回退封顶估算两种情况（依赖 2.1 的真实凭据）
